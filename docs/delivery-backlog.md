# 交付边界与后续优先级

更新：2026-10-05（Asia/Shanghai）。执行顺序遵循“先完成主体框架、核心流程并提交一轮，再完善细节”。当前交付定位为可运行的功能试用候选；完整生产准出标准继续保留，不把未验证项目标为通过。

## 已形成的主体

TypeScript workspace 包含 API、Web、Worker、独立工具执行器、机器 Agent SDK，以及身份、消息同步、任务、Runtime、Action、文件产物、显式记忆、调度、通知和治理模块。核心流程已有真实 PostgreSQL、浏览器、受控工具、S3、本地模型和恢复演练证据。具体执行批次见 [测试报告](testing/test-report.md)。

新交付入口为 [本机试用](operations/local-pilot.md)：初始化、构建、迁移、种子身份、应用进程监督、就绪检查和停止流程。容器制品复用这些独立运行入口和明确配置，不将业务逻辑绑定到开发启动器。

| 后续版本      | 原生设备执行、E2EE、高级工作流、市场、联邦协作                         | 保留设计扩展点；不列为当前已交付能力。                                                                             |

“已记录”不是“已修复”。后续每轮围绕完整用户流程提交，必要回归通过后再进入下一轮；性能和体验优化应附可比较证据。生产准出门禁见 [准出记录](release-readiness.md)，继续独立于功能试用交付。

引用体验细节：消息反应也会提升消息版本，因此在远端反应尚未同步时固定引用，可能触发严格版本冲突。当前保留明确的发送失败状态，不把待发送气泡视为已保存；后续改善重新选择引用和恢复待发正文的体验。此处不能通过静默替换用户选定的引用版本来消除冲突。

交接包清单已补齐：当前 owner 加载待处理行动编号并明确确认披露，接收人可在提案中阅读。发送、修订、接受时校验同任务引用与遗漏，新行动出现须重新核对；已经完成的引用可保留。最多 100 项且超限不截断，子任务行动需按其独立责任和 ACL 分别核对。协议和升级边界见 [实现决策](development/07-implementation-decisions.md)。

组织成员管理的操作、撤权范围和回退兼容边界见 [管理说明](operations/organization-management.md)。旧授权 Run 的常规列表可见性和批量取消体验尚待完善；不得使旧授权复活来解决操作不便。

应用容器部署基线已实现：API/Worker/tool-runner/Web 镜像、同源 HTTPS/WSS、显式迁移、持久化账本和容器业务回归。继续补齐真实环境证书/IdP、业务健康指标、可选外部能力部署实测、容量与恢复验收；配置见 [部署手册](operations/container-deployment.md)。
