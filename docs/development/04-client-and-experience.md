# Imbox 客户端与交互开发设计

版本：1.0；日期：2026-10-04；状态：开发设计，尚未实现。

上级：[开发设计索引](README.md)。接口字段以 [03 接口与 Agent Runtime](03-api-and-agent-runtime.md) 为准。

本篇将产品设计第 3、15、16、18 节落实为 Web/PWA 的路由、状态、同步和交互约束。领域状态、授权、验收与副作用以服务端为准；客户端不能凭聊天文本或本地缓存改变这些事实。

## 1. 技术与代码边界

选定基线为 TypeScript 6、React 19、Vite 8、React Router 7、TanStack Query 5、TanStack Virtual、Radix UI、Tailwind CSS 4、Dexie。版本表示项目选择，不表示各项目的最新版本；具体补丁与兼容插件在 M0 锁定。

| 位置 | 职责 |
|---|---|
| `apps/web/src/app` | 路由、应用壳、用户会话、工作空间切换与错误边界。 |
| `apps/web/src/features` | conversations、inbox、tasks、runs、approvals、artifacts、agents、settings。 |
| `apps/web/src/sync` | 原生 WebSocket、快照/增量协调、投影归并、撤权与重同步。 |
| `apps/web/src/offline` | Dexie schema、本地草稿、消息待发队列、迁移和清理。 |
| `apps/web/src/pwa` | manifest、Service Worker、安装与通知能力检测。 |
| `packages/contracts` / `packages/sdk` | JSON Schema 2020-12、HTTP/事件类型、受控 SDK。 |
| `packages/ui` | 可访问的基础控件、语义卡片、设计 token；不直接读取业务 API。 |

React Router 只管理位置、嵌套路由和导航生命周期；远端业务缓存统一交给 Query。不要同时维护两套独立的路由数据缓存。路由结构依据 [React Router 7 路由文档](https://reactrouter.com/7.18.4/start/declarative/routing)。

Vite 的 Tailwind 集成采用官方插件；颜色、间距、字号、焦点与状态色集中为设计 token。具体安装方式见 [Tailwind Vite 指南](https://tailwindcss.com/docs/installation/using-vite)。

## 2. 路由与布局

以下为客户端 URL，不定义同名 HTTP API。工作空间段只用于定位；服务端必须重新验证成员资格。

| 路由 | 页面与主要行为 |
|---|---|
| `/login` | 发起服务端 OIDC 登录；不接收或持久化 IdP access token。 |
| `/w/:workspaceId/messages` | 会话列表、搜索入口、未读与新建会话。 |
| `/w/:workspaceId/c/:conversationId` | 消息时间线、输入框与按权限打开的详情。 |
| `/w/:workspaceId/c/:conversationId/thread/:messageId` | 线程深链接；父消息受限时使用占位。 |
| `/w/:workspaceId/inbox` | 待输入、待接单、审批、交接、验收、失败升级。 |
| `/w/:workspaceId/tasks` | 按 owner、状态、期限筛选的任务列表。 |
| `/w/:workspaceId/tasks/:taskId` | 目标、契约、子任务、依赖、owner、运行、产物。 |
| `/w/:workspaceId/runs/:runId` | 配置版本、上下文清单、状态、行动回执与用量。 |
| `/w/:workspaceId/approvals/:approvalId` | 固定动作版本的审批与当前有效性。 |
| `/w/:workspaceId/artifacts/:artifactId/versions/:versionId` | 固定版本预览、差异、评论和验收。 |
| `/w/:workspaceId/contacts`、`/agents/:agentId` | 人与 Agent 联系人、能力及可控边界。 |
| `/w/:workspaceId/search` | 服务端授权搜索；敏感关键词不默认写入 URL。 |
| `/w/:workspaceId/settings/:section` | 通知、隐私、设备、显式记忆与授权。 |

`/agents/:agentId` 是上述工作空间下的相对子路由；所有受保护页面处于同一会话边界。资源不可见时使用统一受限/不存在页面，不展示受限标题、作者、成员数或最后更新时间。

桌面布局为导航、主区、详情三栏；移动端详情进入独立路由或抽屉，浏览器返回能恢复原时间线位置。详情深链接可直接加载，不依赖用户先打开会话。

导航保留草稿但不默认跨工作空间搬运内容。切换账号时先终止订阅和请求，再清理账号缓存，最后装载新会话。401 后暂停待发队列；重新认证并确认同一主体后才恢复。

## 3. 状态分层与缓存标识

| 状态类别 | 存放位置 | 权威来源 |
|---|---|---|
| 实体、列表、待处理计数 | Query；允许离线时写入 Dexie | 服务端授权投影。 |
| 选中项、抽屉、筛选 | 路由或局部 React 状态 | 当前用户操作。 |
| 输入草稿、待发普通消息 | Dexie，按主体/空间隔离 | 本地意图；尚非业务事实。 |
| 正在输入、连接状态 | 内存，带 TTL | 临时信号，不进入任务审计。 |
| cursor、投影版本、撤权代际 | 同步模块；可持久化部分进入 Dexie | 同步协议。 |
| 认证凭证 | 浏览器受保护 cookie | API 会话；不可写入前端存储。 |

实体缓存键至少包含 `principal_id + workspace_id + entity_type + entity_id + projection_id`。列表再包含筛选及订阅范围。私人视图和群体视图即使引用同一实体也不能合并。

每份快照保存 `entity_version`、`projection_id`、`projection_revision`、授权代际和获取时间。本地 `entity_version` 映射标准事件的 `entity.version`，不增加另一套 wire 字段。版本为十进制字符串，用 BigInt 或无损十进制比较，禁止转为可能丢失精度的 JS Number。实体版本表示业务变化，投影修订表示此受众可见内容变化；后者可在实体版本不变时因脱敏或授权变化递增。

归并顺序为：校验主体和授权代际 → 校验 projection 身份 → 比较投影修订 → 应用完整替换或明确的补丁。补丁必须声明基础修订；不匹配时拉取新快照，禁止猜测。

同一 projection 的旧响应不得覆盖新修订。不同 projection 的 `entity_version` 大小不构成合并依据。受限占位和删除墓碑也是有修订的状态，不能被迟到 HTTP 响应复活。

Query 的自动重取和重试必须显式配置：读取可按瞬时错误有限重试；403、404、版本冲突停止自动重试。写命令通过统一 mutation 层携带幂等键与前置版本，审批、交接不自动重放。默认行为需参考并覆盖 [Query 默认设置](https://tanstack.com/query/v5/docs/framework/react/guides/important-defaults)。

浏览器重新聚焦先重验会话和授权代际，再恢复敏感查询。Query 的 `staleTime` 和内存回收时间只控制性能，不能被解释为授权有效期。

## 4. 实时同步与重连

浏览器使用同源 API cookie；WebSocket 握手验证会话与 Origin，订阅时再验授权。浏览器不接收 Agent 的短期访问令牌；Agent 认证使用独立机器客户端。

客户端同步状态为 `disconnected → connecting → synchronizing → live`；中断进入 `reconnecting`，游标过期或权限代际变化进入 `resync_required`。界面区分“离线可查看”“正在同步”“已同步”。

采用服务端快照水位与增量流衔接协议：

1. 以当前主体建立订阅，声明支持的事件/schema 版本及已有 cursor。
2. 服务端返回可续传结果，或要求装载新快照及对应续传水位。
3. 同步期间缓冲后续投影事件；快照完成后按该订阅水位应用增量。
4. 先校验、去重、应用投影，再推进已应用 cursor；ACK 不能领先于应用。
5. 进入 live 后持续合并；发生缺口、未知必要控制事件或缓冲溢出则重新同步。

cursor 是绑定主体、订阅、授权代际的不可解释 token。客户端不能拿隐藏的领域全局 sequence 推导缺失消息或受限事件数量，也不能通过数值加一生成 cursor。

持久模式下，相关投影写入和新 cursor 在同一个 IndexedDB 事务提交；随后刷新 Query。进程崩溃只会导致安全重放，不能出现 cursor 已前进但内容未保存。Dexie 的事务用于本地原子写入，具体 API 见 [Dexie 参考](https://dexie.org/docs/API-Reference)。

内存模式下仅 ACK 已应用的内存状态，刷新后重新取快照。不能只持久化 cursor 却丢弃它对应的实体快照。

事件按投影身份与修订去重，实体按前置版本应用。仅保留窗口过期且授权仍有效时，旧缓存可标记不可交互；权限代际变化或无法确认当前授权时，先同步隐藏受影响正文并失效旧代际，再异步清缓存和取新快照，不能只禁用按钮。新授权快照完成后原子切换，避免混合展示两个权限代际。

首版每个标签页保有独立同步会话，避免实现复杂的连接主节点选举。跨页只广播缓存失效、登出和待发队列状态；服务端及 IndexedDB 幂等约束处理重复。

连接退避带抖动；网络恢复、前台唤醒可提前重试。WS 不可用时使用同一授权 cursor 轮询增量，不能切换到无权限过滤的历史接口。

传输 ACK、用户已读和契约接受调用不同命令。滚动进入可见区域且用户隐私设置允许后才推进已读；后台标签页收事件不代表已读。

## 5. 离线与乐观交互

默认仅在内存保存已读业务正文；草稿和普通消息待发队列可按用户选择及工作空间政策本地保存。完整离线历史为显式设置，页面显示保留范围、最近同步时间及清除入口。

| 操作 | 离线行为 | 联网后行为 |
|---|---|---|
| 发送当前会话普通消息 | 展示“待发送”，保留客户端生成幂等键。 | 重验成员资格，按原键提交。 |
| 编辑/删除已保存消息 | 保存编辑草稿或本地待确认意图。 | 获取最新版本，确认后提交；不悄悄覆盖。 |
| 接单、交接、任务修改 | 保存表单草稿，不修改权威状态。 | 重取契约和任务版本，用户重新提交。 |
| 审批、验收、对外发布 | 不排入自动重放队列。 | 展示最新固定版本与有效期，再决定。 |
| 上传附件 | 可保存受政策允许的本地引用；不显示上传完成。 | 获取上传授权，校验大小/类型并开始上传。 |
| 取消运行 | 显示尚未送达的取消意图。 | 服务端确认后显示“取消已请求”，另列已发生动作。 |

待发消息记录 `client_message_id`、scope、草稿版本、依赖附件、创建时间和失败原因。队列状态为 queued、sending、saved、failed；多标签页通过事务领取短期发送租约。

自动待发队列最长保留 7 天；超期停止自动提交并提示用户检查草稿后明确重新发起。不能无限期复用一个早已超过服务端幂等保留窗口的请求。

浏览器在 sending 阶段崩溃后允许以同一幂等键重新发送。服务端响应丢失时，通过幂等查询或消息投影对账；不可生成新键再发送同一条消息。

消息乐观状态只覆盖本地气泡，不提前增加他人已读、不创建假事件顺序、不显示 Agent 接单。服务端实体到达后按 `client_message_id` 合并气泡，避免重复。

任务、owner、审批和预算不做“已成功”的乐观展示。点击后按钮显示提交中，只有权威响应/投影确认后改变状态；版本冲突展示最新差异并保留草稿。

Service Worker 只缓存版本化静态资源及明确允许的离线壳。认证响应、敏感 API、审批正文、对象下载、POST 命令默认不进入 Cache Storage。重试发送由前台同步器承担，不依赖持续后台执行。

本地存储配额耗尽或被浏览器清理时进入内存模式，提示未保存草稿风险并重新同步；不能把 IndexedDB 当作可靠的唯一业务存储。

## 6. 核心组件与呈现契约

| 组件 | 必须展示或保证 |
|---|---|
| `ConversationTimeline` | 稳定 message/projection key、线程、引用、编辑标记、受限占位。 |
| `MessageComposer` | 普通发送、@Agent、委派/咨询候选、草稿、附件状态。 |
| `IdentityBadge` | 人/Agent/服务、实际发送者、受限代理范围；不伪装成人。 |
| `TaskSummary` | owner、责任主体、状态、阻塞项、契约版本及验收条件。 |
| `RequestCard` | 类型、提出者、接收者、期限、接受/拒绝/澄清；送达与接受分开。 |
| `HandoffCard` | 未完成事项、在途动作、接收资格、竞争/过期状态。 |
| `RunCard` | 阶段、等待项、来源、成本、取消；远端状态注明自报/已验证。 |
| `ApprovalCard` | 固定动作版本、差异、目标、数据去向、执行主体、费用与有效期。 |
| `ActionReceipt` | 已提交、成功、失败、未知、核对中；取消不能隐藏回执。 |
| `ArtifactViewer` | 固定版本、来源、评论、差异、验收；新版不继承旧版批准。 |
| `ContextInspector` | 实际输入引用和版本、资料范围；无权来源显示受限占位。 |
| `AttentionInbox` | 待我处理事项、原因、下一动作、有效期；计数由授权投影产生。 |

消息列表采用 TanStack Virtual 处理长列表；它提供虚拟化基础，不定义 Imbox 的滚动、已读和无障碍语义。见 [Virtual 官方介绍](https://tanstack.com/virtual/latest/docs/introduction)。

向上加载历史时保留首个可见消息锚点；流式内容高度变化不把用户拉回底部。用户在底部才自动跟随新消息，否则显示可点击的新消息提示。

流式 token/进度属于临时显示，带 run、输出版本和目标受众；不能冒充持久产物。服务端尚未通过披露检查的私人上下文结果不得先流到群里再尝试撤回。

同一 Run 的低频进度更新现有卡片；等待审批、失败升级与最终交付才产生独立注意事项。完整审计按权限在详情加载，默认不展示隐藏推理。

产物 V1 优先实现安全 Markdown/纯文本、图片和文件下载；代码补丁提供文本差异。支持类型写入能力发现，未知类型展示元数据与受控下载，不加载任意插件。

### 6.1 输入、上传与人工决策

输入框必须正确处理中文输入法组合状态；组合输入期间 Enter 不发送。发送快捷键、换行方式和屏幕阅读器标签在设置与帮助中可发现。

@Agent 只表达被点名或候选任务意图，不直接授予资料读取、接单或工具权限。选择委派后展示范围明确的轻量表单；用户已提供的目标、期限和验收条件预填，缺失关键项才追问。

附件状态区分本地选择、等待网络、上传中、已上传待扫描、可用、被拒绝。消息引用尚未可用附件时显示状态，不允许模型或用户提前绕过扫描读取。

上传中断后根据服务端上传会话续传或重新申请；不重复创建正式附件记录。服务端拒绝时保留可恢复草稿与具体原因，不静默移除附件后继续发送。

同一审批在多个标签页打开时，首个有效决定落库后其他视图显示已处理。其他标签页的陈旧按钮提交应收到明确冲突，并展示权威决定，不产生第二次决策。

“修改后批准”应先产生新的动作提案和差异，再对新版本批准；不能在原审批请求中悄悄替换参数。批量审批首版不提供，避免隐藏不同主体、版本或期限。

验收页面固定任务契约和产物版本，提供通过、拒绝并说明原因、要求修订。新增产物版本后保留旧验收历史，新版本是否需要重新验收由契约明确决定。

收件箱提供稳定事项 ID；同一阻塞项的状态更新修改现有事项，已处理后多设备同步移除。通知消失不删除审计事实，也不能把已读通知当作已处理。

客户端埋点只记录不敏感的交互结果、耗时和错误类别。初版禁止自动采集输入框、审批卡正文、完整页面录像和私人文件名。

## 7. 安全与隐私交互

同源 OIDC 采用服务端会话及 HttpOnly、Secure cookie；写命令带 CSRF 防护并验证 Origin。URL、localStorage、日志、分析事件不能包含 access token、审批正文或私人消息。

收到撤权或会话失效时，先同步使授权代际失效并隐藏受影响正文/显示受限占位，再停止订阅、取消在途查询并清理 Query、Dexie、草稿关联与预览 URL。迟到请求返回也必须经过代际校验，异步清理尚未完成不能成为继续显示旧内容的理由。

私人搜索在服务端过滤，前端不能先下载全部候选再隐藏。结果数量、摘要、排序提示、徽标计数和导航标题同样属于披露面。

消息与 Agent 卡片使用白名单渲染。Markdown 清理 HTML；外链验证协议并使用安全打开方式；禁止 `javascript:`、任意 iframe、内联脚本和 Agent 提供的可执行 HTML。

交互卡片只允许已登记的组件类型和命令 ID。点击时服务端重验主体、资源版本和权限；未知 schema 显示安全摘要与升级提示，不猜测执行按钮。

预览文件先检查扫描状态和真实类型。下载只使用 API 授权网关及 opaque 句柄，浏览器不接收 S3 GET 签名地址；每次请求验当前权限，已传输的字节不能保证撤回。文件名、缩略图和错误文本不能绕过资源 ACL。

显式记忆提供查看、来源、作用域、修改、删除和禁止保存入口。删除确认说明相关派生内容的处理状态；不承诺已下载内容或失联设备立即擦除。

退出登录清理该主体本地内容和推送绑定；共享设备默认禁用持久正文缓存。Web 客户端不能承诺对已经显示、截图或离线保存的信息实施远程强制撤回。

## 8. PWA 与通知

安装、Service Worker、Push、Notification、Badging 分别做能力检测；“可安装”不等于“可接收后台推送”。应用内待处理列表始终是权威入口。

用户点击启用通知后才申请权限。拒绝后不反复弹窗；支持静音、免打扰、时区、通知类别与设备级关闭。权限缺失时保留站内未读，不阻塞正常聊天。

iOS/iPadOS 16.4 起的 Web Push 支持要求将 Web App 添加到主屏幕，并通过直接用户操作请求授权。安装引导必须准确描述此条件，见 [WebKit 官方说明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)。

Push 是尽力提醒，不承担消息可靠投递。payload 默认只包含不敏感的提示和不可猜测定位标识；点击后重新认证、验权并拉取最新内容，不直接信任旧通知正文。

后台服务将通知意图持久化，按主体、设备、类别去重合并。发送前重验成员与通知偏好；无效订阅被清理。系统通知未显示不能据此判定业务失败或已读。

登出、切换账号与撤权清理推送绑定；本地可关闭已展示的相关通知，但不能保证已交付操作系统或离线设备上的通知立即消失。因此默认不放敏感内容。

Service Worker 更新先提示可刷新；刷新前保存允许持久化的草稿，保持幂等队列。旧页面、新 Worker、旧/新事件 schema 的短暂共存需要兼容测试。

若试点要求未安装 Web App 的 iPhone 用户也稳定收到通知，必须增补原生/封装客户端及其推送验证；不能把在线 WebSocket 当作已满足该要求。

## 9. 错误、可访问性与性能

错误必须给出可执行下一步：网络中断可重试；未授权显示重新登录；撤权显示受限；版本冲突保留草稿；结果未知引导核对；预算不足交由有权者调整。

用户错误文案不暴露内部堆栈、SQL、秘密或不可见资源存在性。详情可复制无敏感内容的 trace ID 供支持定位。

Radix UI 作为可访问控件基底，仍需验证标签、焦点恢复、键盘顺序、对比度与屏幕阅读器；状态不能只靠颜色。对话框和抽屉关闭后焦点返回发起控件。

进度更新使用适量 live region 通知；流式 token 不逐字触发读屏。虚拟列表提供可理解的位置、加载入口及阅读方式，不能让键盘用户访问不到历史。

国际化把文案与复数规则从组件中抽离。时间存为 UTC，按用户选择的 IANA 时区显示；截止时间同时提供绝对日期，不能只用“明天”。

性能预算在 M0 固定测试设备和网络后记录，并对齐第 05 篇的单会话 10 万条/总计百万历史数据：首屏可交互、切换会话、历史虚拟滚动、重连补齐和内存占用。报告 p50/p95、数据量和环境，不能以开发机演示代替容量结论。

## 10. 客户端验证与完成条件

Vitest 覆盖投影归并、版本冲突、待发状态机与错误分类；fast-check 生成乱序、重复、撤权和墓碑序列，验证旧数据不会复活或跨投影合并。

Playwright 使用隔离浏览器上下文测试两人、两个设备与两个标签页；至少覆盖下表。测试数据来自测试 API，不通过直接改 DOM 伪造状态。

| 场景 | 核心断言 | 产品验收 |
|---|---|---|
| HTTP 与 WS 乱序、断网重发 | 同一消息一个气泡，版本不倒退，已读与 ACK 独立。 | AC-01、AC-02、AC-04 |
| 快照补齐与新事件同时到达 | 无缺口；过期 cursor 后完整重同步。 | AC-02、AC-16、AC-21 |
| 私聊/群聊同时引用任务 | 不合并不同投影，不泄漏标题、计数和来源。 | AC-09、AC-10 |
| 审批打开后动作或产物更新 | 旧版批准失败，用户看到变化与重新确认入口。 | AC-11、AC-12、AC-18 |
| 正在下载/搜索/渲染时撤权 | 后续访问停止，迟到响应和缓存不能恢复正文。 | AC-19、AC-20 |
| 取消与外部结果未知 | 区分取消请求、远端确认和既有副作用。 | AC-13、AC-14、AC-25 |
| 未知卡片、恶意 Markdown/URL | 安全摘要，不执行脚本或未知控制命令。 | AC-21、AC-23 |
| 账号切换、存储清理、升级 | 不串号；允许的草稿保留，幂等队列可恢复。 | AC-02、AC-19 |

主屏幕安装、锁屏 Push、系统权限撤销、免打扰和后台唤醒必须在支持矩阵中的真机验证。Playwright 的 WebKit 引擎测试不能替代 iOS 主屏幕 Web App 的系统级行为验收。

本篇完成条件为上述交互、错误和隐私路径有对应实现与测试证据；仅完成路由页面、静态卡片或演示录屏不代表同步、审批或撤权已交付。
