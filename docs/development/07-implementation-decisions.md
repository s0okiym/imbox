# 实现决策与设计对照

更新：2026-10-04。本文记录实现中的具体取舍，补充前六篇开发设计。容量目标、验收项和生产门槛仍以原设计为准；局部测试通过不能替代整体验收。

## 实现基线

核心 API、Worker、领域逻辑、工具执行器和 SDK 使用 TypeScript / Node.js 24；Web 使用 React、Vite。PostgreSQL 保存权威业务状态、身份分区、预算、租约、领域事件与派发事实。对象存储使用兼容 S3 的私有桶。所有对外数据以 JSON Schema / OpenAPI 为契约，数据库时间裁定期限和租约。

精确依赖版本以 `pnpm-lock.yaml` 和 `pnpm-workspace.yaml` 为准。浏览器持久数据采用 Dexie 4.4.6；虚拟列表已接入 TanStack Virtual 3.14.13，配合固定分页和有界消息窗口；IndexedDB 单元测试采用 fake-indexeddb 6.2.5。路由当前采用浏览器 URL / History API，没有把设计中的 React Router 7 静默升级成不同主版本。后续引入 Router 时必须保留当前深链语义及权限回归。[Dexie React 文档](https://dexie.org/docs/Tutorial/React)、[TanStack React Virtual 文档](https://tanstack.com/virtual/latest/docs/framework/react/react-virtual)、[React Router 安装文档](https://reactrouter.com/start/declarative/installation)。

## DEV-ADR-04：数据库直接扫描持久作业

初始设计提出 pg-boss 作为作业唤醒层。当前实现由有限 Worker 扫描权威意图、outbox 和计划 occurrence，使用数据库事务、`SKIP LOCKED`、持有者与递增代际处理领取、崩溃和重复调度。等待人工输入不保持进程内任务或占用数据库连接。

理由是先保证业务意图、预算和执行资格在同一事务中落地，避免同时引入第二套作业身份与租约。当前并未运行 pg-boss worker，不能依据依赖目录中存在这个库声称已使用它。扫描轮询带来额外数据库负载，容量报告必须包含队列积压、锁等待与消息保存延迟。

未来若采用 pg-boss 或独立消息队列，它们只承载唤醒和派发；现有稳定命令身份、发生次数、数据库代际、原子预算和 Action 日志仍为执行权威。不得以队列成功送达代替业务接受或外部副作用确认。

## DEV-ADR-05：文本资源首期边界

当前允许 UTF-8 的纯文本、Markdown、JSON，单文件最大 8 MiB；不支持任意二进制上传，也不把文本验证称作通用杀毒。此限制比原设计的通用文件规模更窄，属于明确的实现边界，必须在发布范围中披露。

资源须经历限定暂存上传、实际字节数 / 类型 / SHA-256 验证、文本检查、发布不可变对象后才可读取。固定 Artifact 版本、评论字符锚点、任务证据与分享均绑定明确版本和摘要。分享通过专门端点读取，不扩展源资源 ACL。原授权、当前接收者、有效期和源墓碑在分块下载中重复检查。

扩大文件种类和上限之前，需要新增扫描、隔离预览、超时、解压配额、下载背压与病毒样本边界验证；不能仅调大环境变量绕过协议上限。

## DEV-ADR-06：知识与披露

记忆是显式对象，保留来源、置信度、人类确认状态及版本。搜索在返回正文、片段和分页结果前检查当前权限；嵌入或索引不构成授权凭据。

Run 上下文只接受明确版本和摘要。创建者与 Agent 均须满足当前来源权限。个人记忆不能直接披露给 Agent；需要未来明确的跨受众披露协议。受控分享目前只授权分享端点的下载，不自动成为 Memory 或 Run 可用来源。

删除来源会立即阻断读取，并擦除关联派生记忆正文、运行上下文缓存、检查点、相关投影与快照。已经下载到应用外或交付给外部供应方的副本不能远程收回，产品必须直接说明这个边界。

## DEV-ADR-07：独立账本和恢复

删除 / 撤销事实、Action 外部派发日志存放在与数据库备份独立的签名文件账本中。接受隐私操作时先验证权限和版本，持久化最小意图，再修改数据库。若数据库事务回滚或恢复到较早备份，启动前重放独立事实；不能凭旧库中缺少回执而复活已删内容。

Action 恢复先冻结执行，枚举独立日志中可能跨越恢复点的事实，包括数据库已丢失的孤立意图。只读查询供应方状态和有权人员的明确确认才能推进核对；不知道是否发生效果时保持 unknown，不能重发来“试试看”。身份降级、所有权变更、会话撤销等未全部覆盖在独立删除 / 撤销账本内，恢复操作还需要隔离服务、检查授权变化及失效会话，不得宣称任意历史恢复会自动完整重建当前所有权限。

真实演练目前采用隔离数据库的 PostgreSQL custom-format dump / restore、对象恢复与独立隐私事实重放。该演练验证实际恢复与删除传播，不等于 WAL PITR 或生产 RPO / RTO 验证。生产准出仍需部署自己的 WAL 归档、对象备份、独立账本保管与完整恢复演练。

## DEV-ADR-08：离线和导出

消息历史缓存默认关闭，由部署许可与设备用户主动选择共同控制；所有工作空间当前继承部署策略。离线发送队列也有服务端开关，最多保留 7 天，按主体、租户与会话隔离。网络恢复后重新验证当前身份和授权，使用原幂等命令身份重试。任务接受、交接和审批不自动离线执行。

导出按当前权限逐页、逐记录、逐块读取，内容包含作用域、生成信息、完整结束标记与前置记录的 SHA-256。浏览器验证完整性后再提供文件下载，最大 128 MiB。导出不是一致性数据库快照；下载过程发生变更时可能中断，应重新申请。导出入口 24 小时后失效，不持久保存可重新暴露的完整导出正文。

## DEV-ADR-09：运行内工具与通知

工具能力不由模型自行扩大。工具授权固定工具/版本/目标/来源/预算，模型仅提出结构化文本；平台派生幂等业务身份，每个 V1 Run 最多一个 Action。提案释放 Run 租约并等待人工审批。审批不等于恢复，必须由人显式恢复后领取新代际，工具派发资格和预算再次验证。外部 Agent 不能审批或恢复自己的等待运行。带工具授权的 Run 不接受计划自动唤醒。

工具效果未知时保留预占预算，阻断盲目重发与 Run 恢复。只读查询原业务键确认事实后结算；显式恢复只生成总结，不重新执行已经完成的工具。Run 与 Task 全祖先预算共同约束消费。

通知保存通用提示和不透明定位 ID，不保存消息正文或私人标题。派发队列独立于聊天投影 outbox，列表、计数和打开事项均按当前权限重新检查。已读与业务完成分离；静音和 DND 控制系统提醒，不隐式批准行动。通知中心、偏好与系统 Web Push 投递已接入；协议/数据库测试与真实厂商送达分开验收，不能将设备登记或通知入库描述成系统提醒成功。

最近消息快照固定最多 200 条及同一快照水位；客户端按服务端截断标记显式请求旧历史，使用权限绑定的不透明分页游标。消息深链单独读取当前消息，并重复检查当前授权，不将 URL 当作权限。

通知派发、模型结构化工具意图、离线装配与性能测量仍须在同一候选完成全回归。最终测试报告应区分单元 / 本地集成 / 浏览器 / 实际外部系统与真机证据，不将未知项改写成通过。

## DEV-ADR-10：应用静态缓存与本机离线数据分离

生产构建生成指纹化 Service Worker，缓存白名单仅包含应用 HTML、构建生成的 JS/CSS、manifest 和图标。API、身份回调、导出、文件下载及对象存储请求不进入 CacheStorage；应用路由断网时只回退静态入口。更新采用浏览器等待旧页面关闭后的默认激活流程，不在已有操作中自动切换版本。开发服务器不注册此 Worker。

消息副本、草稿和队列使用独立 IndexedDB，须同时满足服务器许可和用户对该设备的选择；不存在“因为安装 PWA 就默认缓存私聊”。离线入口明确标记为本机副本，不能冒充当前已认证会话。重新联网后按当前会话、成员代际、策略、原幂等键处理；离线入口不能审批、接单或交接。退出/身份切换和用户清理会清除本机记录，写事务内再次检查设备选择，避免晚到异步写入复活已清理内容。

缓存上限是 20 个会话各 200 条消息，保留最多 7 天；待发队列上限 100。断网时不能获知远端撤权，因此启用缓存前说明此边界。真实 iOS/Android 安装、系统回收、系统通知和后台行为仍需单独设备验证。

实现参考：[MDN Service Worker 生命周期与缓存](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)、[Vite 构建插件 API](https://vite.dev/guide/api-plugin)。

## DEV-ADR-11：系统推送是有界提示通道

Web Push 使用 `web-push` 3.6.7 生成 VAPID/aes128gcm 请求，自有传输层限制精确厂商主机、公网 IPv4、TLS、无重定向和超时。订阅以独立密钥 AES-GCM 加密，绑定租户/主体/会话/设备，原始端点不进入 DTO 或日志。029 迁移将订阅版本和最多 5 次尝试持久化；订阅轮换隔离旧租约，迟到 410 不能停用新订阅。

系统通道仅显示通用提示，固定打开通知收件箱后按当前权限读取，不承载业务授权、审批或完成状态。操作系统送达不具备 exactly-once 或撤回保证。协议与数据库测试、真实推送服务及移动设备验收分别记录。配置、密钥轮换限制、恢复隔离和设备门槛见 [系统推送运维](../operations/web-push.md)。

## DEV-ADR-12：有界历史窗口与虚拟消息列表

初始快照仍为最近 200 条，界面每次展开 50 条。超过 200 条使用 TanStack Virtual 测量变高行，仅渲染可见区域和邻近行；已读仍由实际可见正文计算，不由虚拟占位高度或传输 ACK 推断。消息 ID 是稳定行键，编辑、撤回及权限代际沿用原消息归并规则。

当前内存浏览窗口最高 1,000 条。到达上限后可沿原权限绑定游标打开更早窗口，释放较新的窗口；这不是服务端历史保留上限。历史窗口继续应用已加载消息的编辑/删除，不自动追加新消息改变正在浏览的范围。返回最新消息显式重取快照、重置历史游标；在较早窗口中先返回最新再发送，草稿保留。权限变化和断线重同步仍服从现有授权视图清理。

浏览器回归使用 1,055 条真实业务消息，验证虚拟 DOM 数量有界、跨过 1,000 条窗口继续访问第一条、返回最新，以及窗口外深链的当前读取/删除。真实移动设备和辅助技术仍需要独立验收。

## DEV-ADR-13：交接时显式披露待处理行动（2026-10-05）

`GET /v1/tasks/{id}/handoff-actions`（机器端为 `/v1/machine/tasks/{id}/handoff-actions`，需 `tasks.read`）仅向当前有权 owner 返回任务版本和当前任务的待处理 Action 编号，不返回参数、凭证或子任务资料。待处理包含非终态行动、尚未成功的必需行动，以及存在开放核对案件的行动。单次最多 100 个引用；超过时明确返回 `HANDOFF_ACTIONS_LIMIT`，不截断后允许交接。

Web 发起交接时加载此清单，非空清单必须勾选披露确认；`WorkProposal.handoff.pending_action_ids` 固定这些编号，接收人可以在接单前阅读。编号披露不授予 Action 详情或底层来源的读取权，也不继承任何工具执行授权。创建、修订和接受均在任务根锁内检查引用属于同一任务，并且没有遗漏当前待处理行动。新增未披露行动返回 `HANDOFF_ACTIONS_CHANGED`；已经完成的已列行动可以保留在协议中，不因正常进展无限重发提案。

旧客户端仍可发送空清单，但任务存在待处理行动时会被拒绝；不能把缺少字段能力当作默许披露。接受失败时发起人通过修订 API，或在 Web 撤回后重新发起，提供最新条款；接收人重新明确接受。拒绝、澄清和撤回不要求清单仍为最新，以免阻断退出流程。

本清单仅描述当前任务的行动；子任务沿用各自 owner、ACL 和协议，需单独核对。交接前已发往外部的调用可继续发生效果；交接后的旧执行授权仍失效，未知结果仍只读核对，不能凭交接事件直接重发。该实现不把编号清单变成工具执行授权，也不修改既有预算或任务验收语义。

## DEV-ADR-14：组织管理员管理工作区成员，旧执行授权保守失效

2026-10-05。组织 owner/admin 的管理权与资源读取权分开；新增目录仅返回工作区和成员元数据，不隐式加入任务/会话。V1 日常入口操作已有 human 成员，Agent 延用安装与凭证生命周期。

成员变更以工作区版本为 CAS，稳定命令身份去重；组织级事务 advisory lock 在 actor/target 授权锁前获得，避免两个管理员互改时的锁升级死锁。目标 tenant_principal 先于目标 membership、workspace 加锁，兼容现有业务入口的授权锁顺序。最后一名有效人类管理员不能在正常命令中被移除。

工作区角色/状态变化递增成员版本，并递增目标 tenant_principal.authz_revision，保守使其租户内旧运行授权失效。降权或停用写入 `revocation.workspace_member` 独立事实；恢复重放将不晚于该成员版本的 active 权限停用，不覆盖更新的明确授权。恢复可能需要组织管理员修复工作区管理员配置，不能为了可用性恢复旧权限。

暂无数据库迁移，但独立账本类型增加构成二进制回退兼容边界。旧读取器必须回移支持；禁止静默忽略未知撤权类型。详见 [操作说明](../operations/organization-management.md)。后续增量已补齐组织级成员生命周期和绑定账号邀请；旧授权 Run 的统一清理界面仍保留在交付清单。

## 组织级成员授权代际

组织成员生命周期使用独立 `tenant_principals.membership_policy_version`（迁移 031）。公开 CAS 仍用成员 `version`，业务执行仍检查 `authz_revision`；独立撤权事实则绑定 `membership_policy_version`，只有组织角色/状态变更及其重放会提升它。这样，工作区权限变更引起的通用版本增长不会被误认为组织级重新授权。恢复旧组织角色/状态时，旧撤权事实保守停用成员；显式更新的组织授权不被旧事实覆盖。

组织管理以租户 advisory lock 串行协调，再获取调用者授权锁和目标成员锁，与工作区管理共用顺序。owner 才能授予/修改组织管理权限，admin 只能管理 member/guest。最后有效人类 owner 和组织停用后的工作区管理员完整性在事务中检查。管理角色不替代资源 ACL；已有 Run 授权不会因恢复成员而重新有效。

## 账号与组织邀请（迁移 032）

全局人类会话增加不依赖组织的账号入口，供未入组用户取得自己的 principal UUID 和安全退出。邀请绑定现有 human UUID、工作区与 member/guest 角色；接收人先预览组织与权限，再明确确认。预览不授予访问，接受时重验身份、组织、邀请者授权修订/全局版本和数据库期限。保持组织强制 RLS，不按邮箱或显示名称猜测绑定，不添加全局人员目录。

码以域分离 HMAC 可重复生成，表中仅保存摘要；列表、事件和命令回执不保存明文码。组织锁与幂等命令序列化创建/撤销/接受，消费前写独立账本，消费后重试不恢复已撤销成员。账本成功而数据库失败时保守使旧码失效，需复核重发。权限改后恢复不会复活原邀请；已交付码不因密钥轮换自动撤销。完整操作与回退边界见 [邀请手册](../operations/member-invitations.md)。

## 未知展示投影兼容

Web 接收端对协议/schema v1 中格式有效、范围与授权代际一致的未知投影实体，显示固定本地提示并继续消费游标。未知 payload 的 summary、链接、正文和控制字段均不用于展示或执行，也不写入消息缓存；因此不会把未来私有字段或不认识的模板当作 HTML。已知 message 缺少必要字段仍拒绝，不以降级吞掉损坏消息。

此兼容分支只处理 projection.upsert/remove，不扩展服务器写入契约或机器权限。未知控制帧、protocol/schema 非 1 和跨范围/代际投影仍拒绝并进入既有恢复流程。提示在快照完整应用后展示，切换/撤权/退出清理；不把尚未定义的新协议解释成 v1。完整旧客户端/新服务器滚动升级及 Action schema 矩阵仍是 AC-21 验收缺口。

## 任务树默认限制

当前业务默认最大五层（根计第一层）与每棵树最多 200 个任务（包含根）。委派在接受事务中持有根锁并核对父版本、节点数与祖先深度，超限不创建子任务、参与关系或协议。此上限不是租户总任务数限制，也不替代全祖先预算、四并发槽、20 步和运行期限约束。更改限制须同步调整产品策略、持久状态兼容和边界回归；多 Agent 唤醒/多租户压力仍独立验收。

## 已追平同步游标的空页

实时事件读取仍在每次事务内重验身份与当前权限、成员/保留代际和签名游标，锁定投影流后再判断游标是否已在 head_seq。相等时无需访问明细表，直接保持原游标返回空页；不共享完成的授权缓存。流发生变化仍按原明细过滤路径读取，撤权在空页分支之前拒绝。短测只证实少一次无结果查询，不据此声称吞吐或可见延迟达标。

## 通知满批调度

通知 dispatcher 通过实际处理页数报告 batch_full，部分收件人分页也计入处理，不以 completed=0 推断队列空闲。Worker 每轮给每个租户一个有界批次；满批且无失败时仅让出事件循环，空闲/失败保留 250 ms 退避。此提示不是持久队列事实，允许恰好满批排空后多一次空探测。清理和外部 Push 循环继续独立受限，停止信号在当前批次边界生效。

## 2026-10-05 任务产物的多人版本编辑

任务范围内的 Artifact 继承任务写入角色：当前 owner/contributor 可追加不可变版本，reviewer/observer 仅可读。每次提交在事务内重验主体、工作区、当前任务参与角色和祖先状态，再锁定 Artifact 并校验版本；并发写入仅一方提交成功。Artifact.created_by 仍记录最初创建者，每个 ArtifactVersion.created_by 记录实际提交者。此规则同样适用于既有任务产物；团队应将 contributor 视为包含产物编辑的写权限。

会话范围 Artifact 继续只允许创建者追加版本，不因会话成员具有发言权限而扩大编辑权限。分享与底层资源删除的授权规则独立，不随任务版本编辑开放。任务完成/归档及当前权限变化继续阻止写入。

StoredArtifact 增加可选 can_append_version，表示响应时的当前编辑能力，Web 用它显示入口；旧服务端缺少此字段时入口默认关闭。该字段不是授权凭证，提交仍重新检查。无需数据库迁移，也不为每个 Artifact 引入另一套可与任务成员状态不一致的编辑授权。
