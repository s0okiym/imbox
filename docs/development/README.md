# Imbox 开发设计文档

版本：1.0 · 日期：2026 年 10 月 4 日 · 产品基线：[产品与系统设计 v2.0](../imbox-product-and-system-design.md)

本组文档将产品要求落实为可开发、可验证的技术方案。当前交付物是开发设计，目录示例、接口、SQL 和命令均为待实现规范；仓库尚未包含可运行应用、已部署服务或已通过产品验收的实现。

## 已选定的实现方向

主语言采用 **TypeScript 6**，服务端采用 **Node.js 24 LTS + Fastify 5**，Web 采用 **React 19 + Vite 8**，权威数据采用 **PostgreSQL 18**，异步作业采用 **pg-boss**，文件采用 **S3 兼容对象存储**。使用模块化单体、独立 Worker 和工具执行进程，通过 JSON Schema / OpenAPI 与 WebSocket 为人类客户端及外部 Agent 提供统一契约。

这些是选定基线，不声称每个版本都是最新。精确补丁、镜像 digest 和兼容插件版本在 M0 锁定并测试；生产环境不得依赖浮动 `latest`。

## 文档权威与变更

- 产品语义和 INV/AC 编号以产品设计为准，本组文档明确其实现方式；冲突时必须修正文档，不默默降低产品要求。
- 表结构和事务以 02 为准；接口及状态消息以 03 为准；客户端按 04 消费；策略和部署基线以 05 为准；工作安排和质量门禁以 06 为准。
- M0 需要产出版本化 schema、初始迁移、最小运行骨架和依赖锁文件，此前 Markdown 中的示例不替代可执行契约。
- 已选默认方案可在证据支持下调整，变更需写明原因、兼容与迁移影响，并更新关联测试。引入第二主语言、第二权威状态系统或降低执行边界，需要单独设计决策。

## V1 边界

先实现 Web/PWA、人际通信、任务和契约、一个托管 Agent 与一个受控外部 Agent、有限工具、行动审批、产物版本、基本记忆和可靠恢复。原生移动端、任意代码执行、完整设备 Agent、端到端加密、公开 Agent 商店、跨组织联邦和复杂工作流编排保留接口，按产品阶段推进。

开发按第 06 篇的工作包执行。先验证权限、事务和恢复，再扩大功能与负载；原型功能完成不能替代 V1 的全部验收门槛。
