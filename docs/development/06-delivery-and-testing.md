# Imbox 开发工作包、里程碑与验证计划

版本：1.0；日期：2026-10-04；状态：交付设计，尚未实施。

上级：[开发设计索引](README.md)。容量与恢复目标以 [05 安全、部署与运维](05-security-and-operations.md) 为准。

本篇将产品设计第 2 节的 INV-01～16 和第 23 节的 AC-01～25 转为可追踪工作包与发布门槛。这里的目录、脚本、测试 ID、运行环境和命令均是待建立的约定，不表示仓库已有实现或测试已经通过。

## 1. 执行原则与开发基线

先冻结领域语义、协议与失败行为，再逐步交付纵向场景。每个工作包必须同时交付成功、拒绝、冲突、撤权和恢复路径；不把这些留到界面完成后补做。

基线采用 pnpm workspace；TypeScript 6、Node.js 24 LTS、Fastify 5、React 19、Vite 8、PostgreSQL 18、Kysely + pg、pg-boss 和 S3 兼容对象存储。具体补丁版本、容器镜像和 lockfile 在 M0 固定。

Node 24 为 LTS；Fastify 5 要求 Node 20+；当前 pg-boss 文档要求 Node ≥22.12、PostgreSQL ≥13。项目基线满足这些最低条件，仍须验证实际插件组合，见 [Node 发布](https://nodejs.org/en/about/previous-releases)、[Fastify 5](https://fastify.dev/docs/latest/Guides/Migration-Guide-V5/)、[pg-boss 要求](https://pgboss.io/)。

不以“最新”作为自动升级依据。协议、安全修复和依赖升级都必须跑相应契约、迁移与回归检查；JSON Schema 2020-12、OpenAPI 3.1.1 的生成与校验组合在 M0 实测。

里程碑按完成条件管理，不给出缺乏团队、连接器和运行环境依据的精确周数。估算采用区间，先确认身份供应方、首批工具、通知目标设备、恢复目标和可用测试环境，再评估并行度与关键路径。

若要削减 V1，只能明确修改产品基线和验收范围；不能通过跳过 AC、仅保留成功路径或把未实现的安全能力写成“后续优化”降低发布门槛。

## 4. 测试组织与夹具

| 层级 | 工具与计划位置 | 验证对象 |
|---|---|---|
| 状态机/纯逻辑 | Vitest；各 `packages/*` 邻近测试。 | 转移、前置条件、预算运算、授权决策、版本比较。 |
| 性质与序列 | fast-check；domain、policy、web/sync。 | 任意重复、乱序、拒绝、撤权、取消重开序列下的不变量。 |
| 数据库/队列集成 | Testcontainers + PostgreSQL 18；`packages/testkit`。 | 真实事务、锁、唯一约束、迁移、pg-boss、outbox。 |
| API/WS 契约 | Vitest + 真实 API/WS；`tests/integration`。 | schema、认证、投影、错误语义、cursor、重放和兼容。 |
| 浏览器闭环 | Playwright；`tests/e2e`。 | 多上下文、离线、冲突、审批、受限内容、可访问性。 |
| 外部连接器 | 沙箱供应方 + 契约套件；`tests/connectors`。 | 幂等键有效期、查询、条件写入、超时与取消真实边界。 |
| 负载与恢复 | k6 + 进程/网络故障驱动；`tests/load`、`tests/recovery`。 | 背压、重连、消息/模型隔离、备份与删除重放。 |

这些 `tests/*` 为计划增加的顶层验证目录，不替代约定的 apps/packages 源码结构。测试所需 fixture builder、可控模型、假时钟、屏障、网络代理和假连接器放入 `packages/testkit`，生产包不能反向依赖它。

统一种子数据至少包含两个租户、三个人、两个托管 Agent、一个受控外部 Agent、两个设备、私聊与项目群、受限文件和支持/不支持幂等的两类工具。

固定测试 ID 为 `T-AC-01`～`T-AC-25` 与 `T-INV-01`～`T-INV-16`；一个 ID 可对应多个分层用例。覆盖清单记录测试路径、命令、执行环境、结果、证据链接和失败责任人。

确定性模型用于验证编排，不用于声称真实模型质量。真实模型评测单独记录版本、输入许可、费用、误差和可重复范围，不让外部模型抖动阻塞纯状态机测试。

### 4.1 数据与执行隔离

集成套件使用独立数据库或独立测试实例，并为租户、对象存储前缀、队列和外部幂等键生成测试命名空间。并行测试不能共享可变默认租户。

所有测试凭证仅能访问沙箱资源，测试入口与故障注入开关不打包到生产构建。启动时若检测到生产域名或生产账号，真实副作用测试必须拒绝运行。

清理器仅处理本次运行登记的资源；不得以清空整个数据库、桶或外部账号作为通用 teardown。失败时保留脱敏证据，并记录需要人工清理的外部资源。

迁移测试包含空库创建、上一支持版本升级、滚动部署兼容及大表迁移锁影响。并非所有 schema 都能安全 down-migrate；无法逆向的变更需要前向修复或恢复流程。

数据库时钟、应用时钟和模型时间分别控制。租约测试以权威存储时间为依据，调度测试显式指定时区，避免测试机时区或快速执行掩盖过期错误。

安全测试使用独特的无害标记代表受限信息，并在 HTTP、WS、搜索、通知、日志和导出中检测泄漏。不能把真实私人数据写入 fixture 来追求“真实”。

## 7. 并发与故障注入设计

至少两个 API 实例、两个 Worker、两个浏览器上下文和可控外部工具参与竞态测试。用显式屏障暂停在读取版本、批准后、提交前、提交后、写回前等位置，避免仅靠随机 sleep 碰运气。

| 故障点 | 注入方式 | 恢复后的硬断言 |
|---|---|---|
| 业务已提交、outbox 未发布 | 提交后杀进程，再启动消费者。 | 事件最终可见且消费幂等，无孤立业务变更。 |
| 外部动作完成、回执未写入 | 工具提交后断连接或杀 Worker。 | unknown/核对，不由自动重试产生第二次动作。 |
| 交接接受与旧 Worker 提交 | 两事务屏障释放并控制先后。 | owner/epoch 一致，旧代际不能领取新的执行资格。 |
| 取消父任务与子任务执行 | 延迟后代状态广播并恢复旧 Worker。 | 执行点检查祖先有效性，传播间隙不能绕过取消。 |
| 两个任务争抢最后预算 | 同时读余额，再并发预占。 | 数据库约束使总预占不超过授予，失败方无副作用。 |
| 跨根依赖同时添加并共同成环 | 初始 A→B、C→D，并发提交 B→C 与 D→A。 | 租户图锁串行查环，至少一条新边被拒，不能形成循环。 |
| 租约过期且尚无人接管 | 停心跳至到期，在新 Worker 领取前恢复旧持有者。 | 即使 generation 未变也拒绝心跳和普通提交，重新领取必须增代际。 |
| 投影较小序号事务迟提交 | 两事务竞争同一 stream_head，控制提交屏障。 | 序号分配与提交顺序一致，客户端不会越过迟到事件。 |
| 同一事件多受众独立处理 | 延迟一个 scope 的 projector，先完成另一个。 | 各 scope 有独立 checkpoint/receipt，不互相吞掉事件。 |
| 快照与 WS 订阅衔接 | 在快照水位边界持续写事件。 | 无遗漏、重复安全，cursor 与快照一致。 |
| 撤权与慢 HTTP 响应 | 延迟旧响应，先应用撤权事件。 | 前端代际检查拒绝旧正文，后台披露路径拒绝。 |
| 新旧部署重叠 | 旧客户端/Worker 与新 API/schema 共存。 | 未知展示安全，必要控制不兼容时明确失败。 |
| 数据库/对象存储恢复 | 恢复旧快照，保留独立删除账本。 | 墓碑和撤销完成后才开流量，未结 Action 先核对。 |
| RPO 窗口丢失已成功 Action | 外部成功后恢复到尚无 Action 或仍 pending 的数据库快照。 | 独立行动日志重建核对范围，不能依据恢复库旧状态自动重发。 |

pg-boss 可重试失败/过期作业；事务 Worker 仅保证同数据库事务中的写入与作业完成原子提交，不能覆盖外部 HTTP。长模型调用和审批等待不得持有长事务，见 [Workers](https://pgboss.io/api/workers) 与 [Jobs](https://pgboss.io/api/jobs)。

pg-boss `localConcurrency` 是单进程上限，文档说明 `groupConcurrency` 在竞争时可能短暂超额；不能用它验证硬预算正确性。硬配额应由领域事务预占实现，并以上表的并发反例测试验证。[Workers](https://pgboss.io/api/workers)

定时套件覆盖 UTC、Asia/Shanghai 和一个存在 DST 的 IANA 时区。系统调度记录计划时刻、时区、版本、occurrence 与错过策略；不能让服务器系统时区决定用户任务。pg-boss 当前默认 UTC、错过默认跳过，补一次也不等于补齐全部，见 [Scheduling](https://pgboss.io/api/scheduling)。

## 8. 计划命令与 CI 门禁

下列为 M0 以后的计划命令，除 pnpm 自带的 install 外由根 package.json 脚本提供；当前文档提交不执行它们，也不声明这些脚本存在。先按第 05 篇建立环境、迁移和种子数据，再由 workspace 调度对应 apps/packages 和 tests 套件。

```bash
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm contracts:check
pnpm test:unit
pnpm test:property
pnpm test:integration
pnpm test:e2e
pnpm test:connectors
pnpm test:recovery
pnpm test:acceptance
pnpm test:load
pnpm build
```

`test:acceptance` 汇总 AC/INV 证据与缺失项，不把同一全部套件无条件重复执行。`contracts:check` 检查 schema、OpenAPI、生成类型同步及兼容性；破坏性变更必须有版本与迁移策略。

本地集成需要可运行容器的环境、测试专用 PostgreSQL 18 和对象存储服务；真实连接器测试需要隔离沙箱凭证。缺少环境时标记“未验证”，不能用跳过后的绿灯替代通过。

| 触发点 | 必跑门禁 | 产出 |
|---|---|---|
| 每个 PR | 格式/lint、类型、schema、相关单测/性质测试、真实数据库集成、构建。 | 测试报告、反例种子、迁移与契约差异。 |
| 涉及客户端/协议的 PR | 增加关键 Playwright、旧 schema/投影兼容检查。 | trace、失败截图、版本矩阵。 |
| 涉及 Action/权限/Runtime 的 PR | 增加对应并发故障与拒绝路径。 | ActionAttempt/Receipt、审计和无重复副作用证据。 |
| 主分支/周期构建 | 完整 E2E、AC/INV 覆盖汇总、依赖与制品检查。 | 可部署候选制品和缺口清单。 |
| 发布候选 | 全 AC/INV、连接器沙箱、恢复、负载、真机通知和回退演练。 | 发布报告、已知限制、运维签收与回退入口。 |

CI 不使用生产凭证，失败输出清理敏感字段；下载测试制品需权限与保留期。重跑只能用于诊断，反复失败不能通过忽略 flaky 测试绕过门禁。

### 8.1 证据登记与异常处理

每次候选发布保存 commit/制品标识、依赖锁摘要、数据库迁移版本、客户端版本、测试环境、种子、执行时间及报告位置。报告中的通过结论只能指向实际执行过的组合。

AC 证据可以复用同一场景的不同断言，但必须逐项登记。INV 专项失败属于阻断项，即使对应 AC 的界面流程成功也不能发布。

网络故障导致真实连接器套件无法执行时标记受阻，保留已有通过证据的适用版本；不得自动把外部测试切成模拟器后标记同一用例通过。

性质测试失败需保留最小反例和随机种子，修复后将该反例加入固定回归。负载测试不靠增加重试次数掩盖丢事件、越权或重复副作用。

不同浏览器、移动系统或连接器的能力差异记录为支持矩阵。超出已验证矩阵的设备可允许尽力使用，但不继承对应后台推送或恢复保证。

## 9. 负载、运营与发布验收

初始目标采用第 05 篇第 7 节的 1,000 在线连接、持续 50 条消息/秒、20 活跃 Run、总计百万/单会话 10 万条历史。M0 固定参考设备、网络和基础设施，M6 按相同基线测量；调整目标需记录 ADR 和原因，不以未经验证的数字宣称容量。

负载报告至少包含消息保存与投影可见 p50/p95、断线补齐耗时、队列等待、数据库锁等待、错误率、Worker 恢复时间和资源用量。安全计数独立报告：越权输出、错误重复副作用、绕过授权预占必须为零；外部账单超估算另行核对，不与事务预算违规混为一谈。

分别测稳定负载、重连风暴、模型缓慢、文件处理拥堵和单租户噪声。验证任务执行资源饱和时普通通信仍符合约定降级范围，不能只看平均 HTTP 吞吐。

运行手册覆盖死信处理、unknown Action 核对、owner 失效、凭证撤销、迁移失败、删除恢复与通知故障。告警携带可访问 trace ID 和处置入口，不附私人正文。

RPO≤5 分钟、RTO≤60 分钟采用第 05 篇初始目标，部署前固定备份配置并以真实演练验证。恢复服务开放前检查独立删除/撤销/行动账本、outbox 和跨恢复点副作用；业务库可丢失的 RPO 窗口不能成为重复外部动作的理由，无法核对时保持执行冻结。回退代码不能回退已完成外部事实。

## 10. 工作包与版本完成定义

- 实现与当前产品/开发契约一致；偏离有 ADR、影响分析及明确批准记录。
- API、事件、数据库约束、错误和授权路径完整；机器接口与客户端具有相同业务语义。
- 每个相关 AC/INV 有测试路径和可检查证据；失败、撤权、并发、恢复已覆盖。
- 迁移可在空库和上一发布版本验证；旧客户端与滚动部署兼容范围已说明。
- 真实外部工具的幂等、查询和取消能力经沙箱验证；限制如实写入工具定义。
- 不以模拟模型成功证明产品质量；不以模拟连接器证明第三方副作用恰好一次。
- 日志、指标、审计、trace、告警与运行手册可定位实际失败且不泄漏秘密。
- 客户端具备受限、离线、冲突、过期、unknown 和权限撤销状态，并完成目标设备验收。
- 数据导出、删除、保留和备份恢复完成闭环；明确不可强制撤回的外部/离线副本。
- 依赖锁定、制品可复现，发布与回退演练有记录；未验证项不能被标记完成。

M6 的最终交付是可运行的受限 V1、完整验证报告、接口与接入示例、部署及运维资料。本文仅制定该交付计划，不能作为任何实现已通过验收的证据。
