# 05 安全、部署与运维开发设计

版本：1.0 · 2026-10-04 · 上级：[开发设计索引](README.md)

## 1. 信任边界与控制目标

浏览器、设备 Agent、外部 Agent、聊天/文件/网页内容、模型输出和工具结果均不具有平台控制权限。API 验证身份与输入，application/policy 判定业务权限，数据库约束提供一致性和租户纵深隔离，tool-runner 控制平台代执行的动作。

V1 不接受任意可执行插件或模型生成的 shell。托管 Runtime 只编排受控模型和工具；工具进程与 API、数据库管理面分开网络和凭证。未来任意代码执行必须增加专用沙箱、网络出口、资源限制和逃逸验证，普通 Docker 进程隔离不能直接当作多租户不可信代码安全承诺。

外部 Agent 的平台外凭证和网络不在平台控制内。契约、认证和回执可以提高可追踪性，不能证明远端删除了全部数据或停止了全部执行。

## 2. 统一 PolicyPort

PolicyPort 输入：AuthContext、主体/安装/代理关系、当前 tenant/workspace、资源和来源版本、请求动作、处理目的、目标受众、执行位置、Task/Run/grant 代际、预算与时间。输出为 `allow / deny / require_approval`、稳定 reason_code、有效范围与决策依据版本。

V1 显式实现 RBAC、资源 ACL、限定 CapabilityGrant、代理范围和 deny 规则；不引入用户可上传执行的任意策略脚本。owner、会话成员、任务链接和能力发现仅提供关系，不代替上述检查。

| 入口 | 必须判定 |
|---|---|
| 消息读取/历史/线程/引用 | 成员资格、历史可见区间、资源 ACL、删除状态。 |
| 任务关联和摘要发布 | 任务本体读取与投影受众披露分别判断。 |
| ContextManifest 组装 | 当前来源访问、处理目的、模型/执行位置允许范围。 |
| 模型输出和产物分享 | 来源限制、可披露受众、脱敏或授权发布要求。 |
| Action 领取和执行 | 当前身份/安装、祖先授权、任务和租约代际、审批、预算、资源前置版本。 |
| 搜索/下载/导出/通知 | 当前授权与来源限制，片段、标题、计数、缩略图均纳入。 |
| 外部结果提交 | 真实 installation、协议/契约/租约版本、产物 schema 和当前披露。 |

业务命令的拒绝是显式可测试结果，不通过让模型重写提示词“尝试遵守”来实现。敏感决策的 fence 加锁与撤销线性化按第 02 篇执行。

## 3. 输入、披露与内容出口

### 3.1 上下文与提示注入

可信系统配置与不可信内容分开传给模型，所有来源保留 origin、version、classification 和用途。模型的 tool call 仅是候选；对“读取其他租户”“转发秘密”“提升权限”的指令，策略和行动网关必须拒绝。

权限不足时不得用模型自行概括受限原文作为绕过方式。对于私人及团队混合输入，默认产物采用保守披露限制；向群聊流式输出前也需确定该受众允许，不能先泄漏 token 再在最终消息阶段拦截。

个人 Agent 可生成私有草稿，再通过独立发布/脱敏流程交付更广受众。披露扩大只能由对相关来源有处分权的主体批准；仅为 Task owner 不足以批准其他人的私人信息。内容检测辅助判断，不被当作完整语义防泄漏证明。

### 3.2 文件与可执行内容

上传限定大小、类型与对象键；服务端读取真实元数据和 checksum，再扫描。开发及试点默认单文件 25 MiB、普通文本提取上限 5 MiB；较大文件需显式限额和异步管线。扫描器采用可替换适配器，M0 固定本地/生产实现并验证失败关闭策略。

压缩包限制展开层数、总字节和条目数；解析 PDF/Office/媒体使用受限进程。未知或异常类型不能直接在同源页面执行。Markdown 清理 HTML，图片代理/外链预览不得成为 SSRF 入口。

下载默认经过 API 授权网关，opaque 下载句柄只是定位信息，每次请求仍须认证和当前验权；S3 GET 签名地址留在服务端，不直接发给浏览器。长流在设定边界重验并可中止后续传输，已经发出的字节不可能撤回。上传签名仅写暂存前缀，撤权后 finalize 被拒，残留对象由清理器处理。

### 3.3 网络出口

工具端点来自管理员审核的连接器配置；用户输入 URL 需经协议、主机、端口和解析后 IP 检查。限制私有/回环/链路本地/元数据地址、重定向次数、响应大小和 DNS 重绑定；真正连接地址必须与已检查地址一致。

Web Push 的 endpoint 也属于外部目的地，发送进程不能因用户提交 URL 就访问内部网络。V1 外部 Agent 主动拉取，暂不开放任意回调地址；未来 Webhook 需要签名、nonce、时间窗、去重和相同出口检查。

## 4. 会话、秘密与机器身份

OIDC IdP 负责登录和账号验证，平台负责会话、成员、Agent 安装、角色与资源授权。IdP subject 映射使用 issuer+subject，不能把 email 当作永久唯一身份。会话 ID 为高熵 opaque 值，库内只保存摘要和失效信息；登录后轮换会话，敏感授权按策略二次确认。

秘密分为数据库凭证、IdP client secret、模型密钥、连接器密钥、token 摘要密钥、cursor 加密密钥和对象存储凭证。开发通过被忽略的本地环境文件或 secret mount 提供，生产通过独立 secret store 注入；不进入构建参数、浏览器 bundle、模型上下文、git 或测试制品。

每个进程只获得必要凭证。tool-runner 通过动作范围的短期授权读取对应秘密，不能枚举其他连接器；短期能力令牌限制 audience、action_id、参数指纹、用途和有效期。轮换保留必要的验证窗口，撤销立即失效新准入。

cursor 密钥与认证密钥分离；AEAD 包含 key_id 便于轮换。已过期密钥或授权 generation 的游标要求重同步，而不是降级成无签名序号。

## 5. 数据保留、删除与备份一致性

以下为试点默认配置，管理员可在明确范围内调整，用户应能看见实际策略；它们是产品/运维选择，不构成适用于所有组织的法律保留结论。

| 数据 | 初始默认 | 处理方式 |
|---|---|---|
| 消息和普通产物 | 365 天，项目可配置更长 | 到期按权限与依赖处理，生成可同步墓碑。 |
| 临时模型输入/Run 检查点 | Run 终结后 7 天 | 清除敏感正文，保留必要来源 ID、版本和受限诊断元数据。 |
| 增量投影 delivery / 普通幂等记录 | 30 天 | 超窗 cursor 重同步；Action 业务去重单独保留。 |
| 应用日志/诊断 trace | 14 天 | 源头脱敏，分级访问。 |
| 审计与用量元数据 | 180 天 | 最小字段；对隐私主体采用可治理映射。 |
| unknown Action、未结预算与核对 | 直至明确处理完毕，再按相应策略 | 不能按队列清理周期消失或自动释放费用。 |
| 独立行动意图/回执日志 | 不短于 180 天及相关核对/备份窗口，未结记录延长 | 保存最小身份、指纹、幂等键与事实，不随业务数据库恢复点一起回退。 |
| 数据备份 | 35 天滚动 | 删除账本保留至少 90 天，并不短于最长备份寿命加安全余量。 |
| 导出文件 | 24 小时 | 每次下载验权，过期删除对象。 |

删除流程：接受并鉴权 → 同事务写墓碑/撤销 generation 与删除意图 → 立即阻断新读取 → 依次处理数据库正文、对象、摘要、记忆、搜索、缓存和投影 → 记录每个目标的状态/回执 → 通知完成或需处理的边界。

删除账本和权限撤销账本必须复制到不会随同一旧备份一起回退的存储/恢复控制面。恢复旧备份后，先合并这些账本、应用清理与失效，再开放查询、搜索和订阅。对象存储若启用版本和复制，要处理所有适用历史版本及副本，不能只删除当前对象指针。

外部副作用同样需要独立行动意图/回执日志：每次发包前先可靠写入意图，确认后才发送，回执独立追加。V1 可用经验证持久性的独立 S3 日志桶/前缀与唯一对象键实现，故障域、权限、保留与恢复操作要与业务库回退分开；这不是通用事件溯源。对应恢复场景必须能保留全部已准入外部尝试，达不到时禁止自动恢复行动，只能冻结并用供应方/人工证据核对。

备份中的删除按声明的到期机制收敛；合法保留或其他组织特殊政策需要单独明确，不能与立即全量擦除同时承诺。已经披露到第三方或失联设备的内容以请求和回执跟踪，不保证强制删除。

## 6. 本地、测试与生产拓扑

### 6.1 本地开发

Docker Compose 基础 profile 提供 PostgreSQL 18、SeaweedFS S3、Keycloak；API、Web、Worker 和 tool-runner 可在宿主开发模式运行。可选 profile 提供模型/工具模拟器、邮件/推送测试接收端和 OpenTelemetry Collector。数据卷和凭证只用于开发，服务默认绑定本地可控接口。

种子任务需要两个租户、三个人、托管 Agent、外部示例 Agent、私聊和群聊、受限文件、可幂等及不可幂等工具。所有资源带测试命名空间，初始化不能碰生产账号。

计划增加的开发命令：

```bash
pnpm env:check
pnpm infra:up
pnpm db:migrate
pnpm db:seed
pnpm dev
pnpm infra:down
```

这些是 M0 要实现的脚本，当前仓库只有文档。`infra:down` 默认保留数据卷，清空数据另设显式命令。

### 6.2 试点和生产

单机 Compose 适合内部试用，不宣称高可用。生产默认拓扑为同源 HTTPS 入口、至少两个 API 实例、按角色独立的 Worker、隔离 tool-runner、托管高可用 PostgreSQL、私有 S3、OIDC IdP 和监控/日志后端。具体云厂商和部署区域在试点约束明确后填写环境清单，领域契约不绑定云。

WebSocket 不要求永久粘滞到特定实例；所有实例从持久投影恢复，短期本地缓冲可以丢弃。数据库连接总数由 API/Worker/queue/listener 分别预算；LISTEN 使用固定会话连接，不能透过事务池模式假装保持订阅。

静态 Web 与 API 可以分别部署，但使用反向代理保持浏览器同源。客户端配置只包含公开服务地址和能力；服务端配置启动时严格校验，缺失策略、秘密或不可接受版本直接拒绝启动。

### 6.3 配置分组

| 分组 | 代表变量/配置项 | 敏感性 |
|---|---|---|
| 服务 | APP_ENV、PUBLIC_ORIGIN、PORT、BUILD_SHA | 普通元数据，公开部分可进入客户端。 |
| 数据 | DATABASE_URL、角色连接、池大小、迁移版本 | 连接秘密不得记录；生产角色分离。 |
| 身份 | OIDC_ISSUER、CLIENT_ID、CLIENT_SECRET、SESSION_TTL | secret server-only；issuer/redirect allowlist。 |
| 内容 | S3_ENDPOINT、BUCKET、凭证、MAX_UPLOAD_BYTES | 桶私有，对象键不含用户原始文件名。 |
| Agent | 模型适配器、模型 ID、provider secret、data region | 禁止客户端直接调用秘密 API。 |
| 授权 | TOKEN_TTL、策略版本、cursor keyring、撤销配置 | 只有有权运维可变更，并审计。 |
| 作业 | 队列并发、轮询、重试、lease、heartbeat | 必须与业务超时和 DB 连接预算一致。 |
| 治理 | 保留期、导出期限、备份/删除账本位置 | 配置变更需评估历史数据影响。 |
| 监控 | OTEL endpoint、日志级别、采样率 | 不允许通过 DEBUG 打开所有正文。 |

## 7. 容量基线、SLO 与背压

以下是待验证的 V1 试点目标，M0 固定参考环境，M6 必须提供实测；不是已实现承诺。参考环境为同区域网络、数据库和对象存储，2 个 API（各 2 vCPU/2 GiB）、2 个 Worker（各 4 vCPU/4 GiB）、至少 4 vCPU/16 GiB 的独立 PostgreSQL，以及独立受控工具进程。模型推理在外部供应方，其延迟单列。

| 项目 | 初始目标/边界 |
|---|---|
| 工作负载 | 50 个试点空间、1,000 个在线连接、合计持续 50 条消息/秒、短时 100 条/秒、20 个活跃 Run。 |
| 数据集 | 至少 100 万条历史消息，单会话 10 万条，中文/英文混合并含撤权历史。 |
| 保存延迟 | 同区域 API 接收至事务提交 p95 ≤ 300 ms，排除客户端公网 RTT。 |
| 可见延迟 | 正常连接下持久保存至目标授权客户端应用 p95 ≤ 1 秒；模型输出单列。 |
| 重连恢复 | 每客户端 1,000 条可见增量在参考网络下 p95 ≤ 5 秒。 |
| 可用性目标 | 生产试点消息/API 月度目标 99.9%；单机试用不适用。 |
| 恢复目标 | 已持久业务状态 RPO ≤ 5 分钟、服务 RTO ≤ 60 分钟，需 WAL/对象备份及实际恢复演练支撑。 |
| 安全门槛 | 已知越权披露、错误负责权切换、盲重试导致重复副作用为零容忍发布缺陷。 |

目标未达标时保留失败报告，调整容量或明确缩小试点支持范围并更新文档；不能仅删测试后宣称完成。预算上限与外部实际账单误差分别呈现，不把“零越权预算”混同为“任何供应方费用绝不超估算”。

背压按 tenant、Agent、连接器和队列分层。消息/API 有独立连接与并发预算；运行、文件处理和导出不得占尽它。受限输入返回 429/503 与可重试信息，不能接受后无记录丢弃。pg-boss 与业务同库时监控锁、I/O、膨胀和归档压力，队列竞争超过预算先调优/隔离，再评估独立队列。

## 8. 可观测性与故障处理

使用 Pino 输出结构化日志，通过 OpenTelemetry 关联 request、tenant、Task、Run、Action、intent、projection 和 trace ID。指标标签只用有限枚举和可控聚合，避免把每个用户/消息 ID 变成无限标签。客户端文本、prompt、工具秘密、完整文件名和内容不默认采集。[OpenTelemetry JavaScript](https://opentelemetry.io/docs/languages/js/)

| 信号 | 告警/处置 |
|---|---|
| outbox/投影最老未处理时间 | 检查消费缺口、死信和锁；按稳定事件身份重放。 |
| Run lease 过期率、模型错误率 | 暂停新派发、核对在途行动、恢复有限步骤。 |
| unknown Action 数量/年龄 | 进入核对队列，指派责任主体；禁止批量盲重试。 |
| ACL/身份拒绝突增 | 分辨过期客户端、策略变更与滥用；不得临时禁用鉴权“修复”。 |
| 预算未结算/差额 | 保留预占和原回执，核对供应方账单后结算。 |
| 数据库锁等待/连接饱和 | 限制后台负载，检查锁序；保证消息准入资源。 |
| 删除传播/恢复墓碑积压 | 保持受限读取，补偿清理，展示未完成状态。 |
| 推送失败 | 清理失效订阅，保持站内 inbox；不改变任务接单状态。 |

数据库不可用时拒绝新的权威提交，客户端只能显示待发送；不能显示已经保存。模型故障时人际通信继续，相关 Run 等待/失败。S3 故障影响附件/产物而不应阻止纯文本消息。队列派发故障时意图保留，恢复扫描重建；若故障来自共享数据库，则不得声称消息服务完全不受影响。

## 9. 发布、回退和恢复流程

1. CI 生成不可变镜像、SBOM、依赖锁摘要、契约和迁移清单；记录 commit 与构建来源。
2. 先执行兼容性 expand 迁移，再部署 API/Worker/客户端。旧客户端、旧 Worker 和新 schema 在滚动窗口内共存。
3. Worker 停止领取新工作，完成有限步骤或让租约过期；未结 Action 进入核对，不由重启直接重发。
4. canary 使用受限测试租户验证消息、审批、外部接单、撤权和延迟，再扩大流量。
5. 回退代码只允许回到兼容当前 schema 的版本；不可逆迁移以前向修复或恢复方案处理。外部行动、审批事实和删除墓碑不能随代码回退消失。
6. 恢复时先封闭外部行动出口，恢复数据库/对象、应用独立删除与撤销账本、验证投影和 outbox。冻结可能跨越恢复点的全部执行范围，从独立行动日志及供应方回执重建核对，包含数据库中已丢失或退回 pending/queued 的 Action；不能只查询恢复库里的 executing/unknown。不能证明未执行者保持 unknown/人工处理，禁止依据旧状态自动重发。完成核对后再逐步开启只读、通信和执行。

数据库备份采用持续 WAL/时间点恢复能力或等效方案，定期验证；对象存储备份和生命周期与数据库引用一起演练。恢复报告包含实际 RPO/RTO、丢失范围、未结行动和删除合规状态，不以“备份任务返回成功”代替恢复验证。

## 10. 运维交付清单

V1 发布前必须提供：环境/支持矩阵、启动与配置说明、数据库迁移、身份与凭证轮换、暂停队列、Run 接管、unknown 核对、死信重放、删除/导出、备份恢复、发布回退、告警与责任分派手册。

应用级管理界面只允许有权主体执行明确操作，必须审计并复用业务用例；不把通用 SQL 控制台或“把任务改成成功”的按钮暴露给普通管理员。运维紧急能力采用独立受审计身份，不能依赖模型发来的文字获得。

端到端加密、跨组织联邦和任意代码执行在后续阶段分别增加威胁模型与实现规范，本篇的传输/静态加密不被描述为已经实现这些能力。
