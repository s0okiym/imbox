# 运行与故障处置入口

本目录记录当前实现可执行的操作边界。生产 TLS、OIDC、备份保管、WAL PITR、目标设备和设计容量仍需在实际部署中验证；本地测试结果不替代这些门槛。

## 环境与启动

本机功能试用可直接使用 [集中启动与停止入口](local-pilot.md)，支持保留配置、初始化、进程监督与就绪检查。

开发/测试使用仓库固定的 Node.js 24、pnpm 10、PostgreSQL 18 与 SeaweedFS。`pnpm infra:up` 只启动本项目的 PostgreSQL/对象存储；`pnpm infra:setup:test` 只配置回环地址的固定测试桶与 4173 Origin CORS。不要使用测试账号或 seed 主体处理业务数据。

先从 `.env.example` 建立仅服务账号可读的配置，替换会话、独立隐私账本及独立行动日志密钥。配置中区分迁移、应用、身份连接；应用和 Worker 启动时验证其数据库角色不具备 owner/BYPASSRLS 权限。环境文件不提交，不在 shell 调试输出中展开。

构建与验证使用 `pnpm verify`；迁移使用显式 `pnpm db:migrate`，不由 API/Worker 自动执行。部署产物保留完整 workspace 的 `dist` 和生产依赖链接；不要单独复制 API 的一个 JS 文件。运行入口分别为 `node apps/api/dist/main.js`、`node apps/worker/dist/main.js`；如启用受控工具，还须按工具执行器配置启动其独立进程。进程服务管理器负责重启和退出超时。

Web 发布 `apps/web/dist`，同源反向代理 `/v1/`（含 WebSocket）到 API，前端资源路由回退到 `index.html`。保留原 Origin、HTTPS 与 HttpOnly Cookie 语义。生产禁止开发登录；PUBLIC_ORIGIN 必须与真实 HTTPS 站点一致。Service Worker 脚本须可更新，认证/API/下载不得被代理缓存。API `/healthz` 只说明进程存活；`/readyz` 检查其配置的数据库就绪条件，不证明整个外部服务生态可用。

Worker 仅处理 `WORKER_TENANT_IDS` 列出的租户。部署时核查完整租户清单，遗漏租户可能保持排队；不默认扫描任意租户。模型 Worker 需显式启用，固定模型名称和摘要，控制并发、内存和成本。托管 Run 的目的地为已配置的本地模型，不能通过表单输入更换任意 URL。

真实用户的首次组织接入使用 [组织与工作区初始化](workspace-provisioning.md)，与开发种子分离；只允许新组织和现有有效人类身份。

## 故障分流

| 现象                   | 核对与处置                                                                                        | 禁止替代做法                                                |
| ---------------------- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 消息已保存但对方未显示 | 核对权威消息、对应 outbox、投影 cursor/代际及 Worker 租户清单；客户端按服务端指示重新同步。       | 不直接修改序号、已读 cursor，或从数据库把私人正文发到日志。 |
| outbox/通知积压        | 查看队列最老等待、失败次数和数据库锁/IO；确认独立派发循环存活，保留原事件 ID 后恢复处理。         | 不删除未完成行来“清空告警”，不把通知成功当业务完成。        |
| Worker 租约过期        | 确认数据库时间、旧进程状态和当前代际，再由正常领取路径恢复；unknown 用量先核对。                  | 不手工延长旧租约或重用旧执行者身份绕过代际。                |
| Action unknown         | 使用行动详情的“查询外部结果”；保留原业务键、指纹、Attempt、回执和费用。                           | 不以重发验证是否成功，不把取消解释为外部效果已撤销。        |
| 恢复后出现孤立行动     | 保持执行冻结；管理员在“恢复核对”只读查询可信证据，确认一次记账并封存，全部案例解决后明确解冻。    | 不通过补零费用、删账本或改数据库状态解冻。                  |
| owner 不可用/过期      | 查看任务阻塞与升级状态，由当前授权管理员显式接管，保留原 owner 与升级审计。                       | 不置空 owner，不无记录地把责任转给活跃用户。                |
| Agent 凭证泄露/失效    | 管理员从 Agent 目录撤销凭证，必要时停用安装；换发新凭证并在外部密钥管理器替换。                   | 不把旧凭证明文放在会话、URL、工单或日志中。                 |
| 订阅失效/系统不弹通知  | 先验证通知收件箱和当前会话，再按 [Web Push 手册](web-push.md) 检查权限、DND、厂商结果及设备能力。 | 不自动重开权限，不承诺已显示或可远程撤回系统提示。          |
| 删除后仍有对象占用     | 先确认读取已被墓碑拒绝，再观察持久清理作业；核对衍生正文、评论、索引和分享撤销。                  | 不把物理回收延迟解释为仍可授权读取；不恢复旧正文绕过墓碑。  |
| 迁移失败/版本不兼容    | 停止新版本上线，保留错误类型及迁移 ID；校验数据库中已登记的不可变 checksum。                      | 不编辑已应用迁移或强行覆盖 checksum；需增加新迁移修复。     |

日志只记录错误类型、请求 ID 和经授权可查询的关联标识。API 已关闭默认逐请求日志，并过滤错误详情；不要临时打开请求体、Cookie、Authorization 或连接字符串输出。生产指标采集、告警路由、历史保留和通知负责人需要在部署中配置并验收，当前尚不把健康端点等同于完整监控。

## 恢复与回退

`pnpm test:recovery` 会新建随机隔离数据库，通过 PostgreSQL 容器实际执行 dump/restore，恢复测试对象，并重放独立删除/撤销事实。它不会向现有业务库执行 restore，也不测试 WAL PITR。报告写入忽略的 `.artifacts/recovery-drill.json`，可按受控方式归档机器可读结果，不归档凭证和对象正文。

真实恢复按顺序执行：隔离入口与所有外部执行器；恢复数据库和对象；装载独立隐私/行动账本；核对日志完整性与固定密钥；重放删除/撤销事实；冻结并核对跨恢复点 Action；复核恢复后的会话、角色、owner 和订阅；重建/对账 outbox 与通知；验证权限及预算；人工决定开放业务读取与执行。

独立隐私账本当前覆盖明确实现的删除与撤销事实，不覆盖所有组织角色和任意外部身份系统的历史变更。因此恢复后必须完成当前身份/权限复核，不能只运行重放命令就开放生产。推送订阅建议清空后重新登记。备份和账本分别保管，密钥不与备份明文放在一起。

代码回退只允许兼容当前已应用 schema 和已发生外部事实的版本；不回退或截断行动账本，不重新执行已确认业务键。生产 RPO≤5 分钟、RTO≤60 分钟仍须通过实际备份策略及演练证明。

## 支持矩阵与发布门槛

已执行的客户端自动化为 Playwright 1.63.0 的桌面 Chromium，包含移动视口、真实 Cookie/CSRF、WebSocket、S3 直传和生产 PWA 离线壳。移动视口不等于 Android/iOS 真机；Chrome/Firefox/Safari 的系统后台通知、OS 权限和生命周期须分别记录结果。

当前外部副作用测试服务为本地受控 HTTP 提供方，真实执行并注入丢响应，可证明本平台不盲重发；它不证明第三方供应商具有相同幂等/查询语义。新增供应商先验证绑定回执、超时、取消及 unknown 处置，再列入支持矩阵。

验收和性能结果见 [测试入口](../testing/README.md)、[容量记录](../testing/capacity-report.md) 和 [实施状态](../implementation-status.md)。完整 AC/INV、最终候选全回归、运维演练及未验证外部边界均不得由“能启动”代替。

## 开发期数据库性能诊断

`createDatabase` 的可选 `observe` 接收固定操作类别/表名白名单、SQL 指纹、查询往返/连接获取耗时和池计数，默认不启用。观察器不接收参数、SQL 或异常正文；同步抛错和异步拒绝被隔离。回调应快速、无阻塞，生产指标出口和告警仍需独立部署验收。

容量探针按 application/identity/worker 汇总，最多 1,024 个指标键，输出前 30 个热点以及截断计数和完整角色汇总。获取连接包含池等待和新连接建立；查询计时从已获取连接开始。累计并发耗时会大于墙钟时长，不可当 CPU 时间。排查时同时看等待数量、每事务往返数、队列年龄和完整送达计数，避免仅扩大连接池掩盖无界读轮询。

日常管理入口见 [组织与工作区成员管理](organization-management.md)，含已有人员添加/角色/停用/恢复及独立账本回退兼容要求。

应用级镜像与 HTTPS/WSS 网关的部署入口见 [容器部署](container-deployment.md)。
