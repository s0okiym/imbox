# 组织与工作区成员管理

入口：Web「组织与成员」。只有当前组织的 human owner/admin 可管理；工作区 admin 本身不授予组织管理权。Agent 使用 Agent 目录及其安装、凭证生命周期，不能通过本入口提升自身权限。

## 日常流程

1. 首次开户继续使用 `workspace:provision`，绑定已有可信身份；日常管理不创建或猜测 OIDC subject。
2. 组织管理员创建工作区，自动成为该工作区管理员。名称上限 120 字，与客户端工作区名称契约保持一致。
3. 从本组织已有有效人类成员中选择人员，指定工作区角色、状态与理由，再明确确认。
4. 停用只撤销该工作区入口，不停用全局身份或其他组织；恢复会重新开放此工作区中仍保留的具体资源 ACL。加入工作区本身不自动加入所有任务或会话。
5. 工作区至少保留一名有效的人类管理员。先增加另一名管理员，再降权或停用现任管理员。组织管理员即便不是工作区成员，仍可管理其成员元数据；这不会授予资源内容访问权。

访客不能新建会话或任务，但工作区角色不会自动清除已有资源 ACL，也不代表所有已有资源都变为只读。若要撤销该工作区的全部访问，应选择停用。

角色、状态变化会增加目标成员的租户授权修订。因此该人在本组织各工作区的旧 Run/Action 授权都保守失效；恢复或提权不会使旧授权复活，新的执行需重新发起。此范围比单个工作区更宽，是当前 V1 选择的安全边界。

## HTTP 契约与并发

- `GET /v1/organization/access`：当前调用者是否可管理。
- `GET /v1/organization/workspaces`：本组织工作区元数据，不等于已加入列表。
- `GET /v1/organization/candidates`：有效的人类候选成员。
- `GET /v1/organization/workspaces/{id}/members`：工作区成员，包含停用成员及只读 Agent 行。
- `POST /v1/organization/workspaces`：创建工作区，需要 CSRF 与 Idempotency-Key。
- `PUT /v1/organization/workspaces/{id}/members`：添加或修改人类成员，需要 CSRF、Idempotency-Key 和以工作区版本为值的 If-Match。

读取列表使用调用者、租户、授权修订及用途绑定的加密游标，每页最多 100 条；成员游标还绑定工作区版本。Web 逐页加载，遇到分页失效会报错，不把截断目录当成完整目录。它定期和重新聚焦时核验管理权限；变更表单不会被后台刷新悄悄重新提交。

成功变更增加成员版本和工作区版本，记录 `workspace.member_changed` 领域事件及同事务 outbox。理由在事件中保存。相同命令重试不会重复变更，版本冲突要求刷新后重新核对；不通过自动重试覆盖他人修改。创建工作区也使用稳定命令身份，响应丢失可用原命令重试。

## 恢复与回退边界

降权或停用 active 成员在数据库提交前写入独立签名账本 `revocation.workspace_member`，记录工作区、成员及撤权前成员版本。账本不可写时变更失败。事实已持久化而数据库回滚时，恢复仍执行该撤权意图；较旧备份里的旧成员权限不能重新生效。

恢复重放在启动监听前完成：旧版本 active 成员变为 disabled，同时增加租户授权修订和工作区版本。恢复采取保守停用，降权前备份不会直接恢复为较低角色；管理员检查后可明确重新授权。比该事实更新的成员版本不会被旧事实覆盖。灾备重放优先保持撤权，可能暂时没有工作区管理员；有效组织管理员可在复核后修复成员配置。

新增账本类型不能由旧版本读取器忽略。回退二进制必须包含该类型的校验及重放支持，或先回移兼容补丁；不允许删除账本事实以启动旧版本。工作区成员管理本身无新增迁移；后续组织级生命周期需要迁移 031，见下文。

## 尚未覆盖

自助邀请、新成员入组、外部身份首次绑定、工作区删除与批量管理仍需后续设计与实现。当前入口只修改已有组织成员，不创建全局身份。

旧 Run 的内容读取仍受创建时授权修订保护，可能不再出现在常规列表。当前仍有资源权限的创建者可通过已知 Run ID 和版本调用现有取消接口，返回内容已清空的结果；管理台中发现及批量清理此类旧 Run 的体验尚待完善。不能把失效运行重新发起视为对旧外部效果的撤销。

## 组织级成员生命周期

“组织成员权限”管理当前组织已有成员的角色和访问状态。所有者可以任免 owner/admin/member/guest；管理员只能修改普通成员或访客，不能修改自己或其他管理员/所有者，也不能授予管理员权限。Agent 使用独立目录管理，历史成员不能直接恢复。停用全局身份的成员不能在此重新激活。

修改使用成员版本的 If-Match、幂等请求标识和明确理由。组织变更与工作区变更共享组织管理事务锁，避免相互降权死锁和最后所有者竞态。必须保留至少一名有效的人类 owner；组织停用也检查其管理的每个工作区是否还有另一名有效人类管理员。增加所有者不自动授予其他会话或任务权限。组织 member/guest 不覆盖工作区角色和资源 ACL，降为组织 guest 不表示所有工作区变为只读；撤销整个组织访问应选择停用。

所有实际组织角色/状态变化提升 tenant authz revision；恢复会重新开放仍保留的具体资源权限，但旧 Run 授权继续失效。旧停用请求的幂等重试不会覆盖之后的恢复。组织停用不删除历史消息、任务或人员，相关责任应通过任务交接另行处理。

迁移 031 引入独立 `membership_policy_version`。角色降级或停用先写独立 `revocation.tenant_member` 事实，存储失败则事务不生效。恢复数据库后重放旧事实会保守停用未被明确组织级新授权覆盖的成员；工作区编辑产生的新版本不能覆盖组织撤权事实。恢复环境可能因此没有可用所有者，必须由受控离线运维核对账本和组织授权后修复，不能跳过重放以恢复访问。

回退旧二进制前，需回移迁移识别以及新账本类型的验证/重放支持；新旧版本直接混跑或仅回滚数据库并不安全。新增人员入组、自助邀请和组织选择仍是后续接入工作，当前接口不支持根据邮箱或名称猜测身份绑定。
