# 账号与新成员邀请

本流程把全球账号认证与组织授权分开。尚未加入组织的人也能查看自己的账号标识并退出登录，不能因此读取组织内容；API 仍要求相应组织和资源权限。邀请只绑定准确的 human principal UUID，不按邮箱、同名显示名称或模型声明绑定身份。

## 人员操作

1. 新用户完成 OIDC 登录，在登录页的“当前账号与入组”区域取得“我的账号标识”。已有组织成员可从导航“账号与加入组织”查看相同标识。
2. 组织 owner/admin 在“组织与成员 → 邀请新成员”填入该标识，明确工作区、member/guest 角色、1～168 小时有效期和理由，再确认创建。
3. 管理员把新邀请码通过自己的可信渠道交给指定用户。系统不自动发送邮件或外部消息；邀请码不放入 URL，不保存在浏览器持久化存储中，刷新或离开页面会清除本次展示。默认使用只读密码字段，可手动复制或点击复制按钮。
4. 指定用户在已认证账号下输入邀请码，先查看组织、工作区、角色及期限；勾选确认后才加入组织及目标工作区，并进入该组织。预览不产生成员关系，接受时重新检查当前权限和期限。此过程不自动授予已有会话和任务的 ACL，也不把任务/Agent 协作的协议接受与组织邀请混为一谈。
5. 尚未接受或已过期的邀请可由管理员填写理由撤销。已经接受的邀请不再撤销入组；使用组织成员管理停用或降权。

同一组织对同一账号最多一个数据库状态为 pending 的邀请。过期记录需要先撤销再重建，避免偷偷替换旧授权意图。已有组织成员（包括 disabled/historical）不能通过邀请重新入组或恢复，必须走正常成员生命周期。邀请只授予 member/guest，后续管理权限由 owner 明确任命。

## 权限与重试

创建和撤销使用版本/幂等命令机制；创建丢响应时同一授权调用者可用原命令重试取回同一邀请码。列表不返回邀请码。数据库仅保存其摘要；码的生成以部署会话密钥作域分离 HMAC，不把密钥写入回执或事件。轮换密钥后，旧命令可能无法重建原码，需撤销后新建；已经交付的旧码仍按存储摘要和原有效期验证，密钥轮换本身不是邀请撤销。

接受只依赖当前有效的人类会话、同源 Origin/CSRF 和绑定的目标账号，不要求尚未获得的组织权限。邀请码包含组织/邀请标识及高熵认证部分，接口不提供租户或全局人员枚举。服务端以数据库时间检查期限，并在独立账本写入后的授权状态转换处再次检查，再检查组织有效、邀请者仍具有创建时的授权修订与全局身份版本、目标仍有效且尚无组织成员记录。

邀请者权限改变后再恢复，旧邀请不会自动复活。并发接受只建立一份成员关系；接受后的响应重试只返回原回执，不重新激活之后被停用的成员。接受与撤销共享组织事务锁，不留下部分入组状态。

## 独立账本与回退

迁移 032 新建强制 RLS 的 `organization_invitations`，运行 application 角色须获得该表的 CRUD 授权，identity 角色不需要该表权限。开发/测试角色初始化已包含授权，生产由运维按现有角色分离手册执行。

撤销和接受消耗都在数据库提交前写独立 `revocation.invitation` 事实。恢复到旧的 pending 记录时，重放使其 revoked，防止旧备份中的邀请码重新授予访问。当前 accepted 或较新的状态不被旧记录覆盖。若账本成功、数据库事务失败，重放仍保守使原邀请不可用；管理员复核后重新创建邀请，不删除账本以重试旧码。

回退版本必须兼容迁移 032 及该账本类型，不允许忽略未知事实或混跑不兼容读取器。邀请码泄露给其他账号也不能完成绑定入组，但仍应撤销泄露的邀请。真实 IdP/公共 TLS、邮件分发、组织自动发现/切换列表以及大规模邀请历史清理仍需各自实现或验收；现有 CLI 首次组织开户继续有效。
