# 系统推送部署与验收

当前已实现 Web Push 协议适配、加密订阅、浏览器授权入口及通用通知处理。数据库/协议回归与实际厂商送达是不同证据。本地开发默认关闭推送；未配置密钥时通知收件箱仍可正常工作。

## 配置

部署应使用 HTTPS，并提供生产构建的 `sw.js`、manifest 和静态资源。用户从通知页面主动请求权限；系统订阅绑定当前租户、主体和登录会话。禁止静默订阅或在登录时弹权限请求。

API 和通知 Worker 需要同一组环境值：

| 配置 | 内容 |
|---|---|
| `PUSH_ENCRYPTION_KEY` | 密钥管理系统生成的 32 个随机字节，base64url 编码；与会话及隐私账本密钥分离。 |
| `PUSH_VAPID_PUBLIC_KEY` | P-256 公钥，base64url，发给浏览器。 |
| `PUSH_VAPID_PRIVATE_KEY` | 对应私钥，只由服务端使用。 |
| `PUSH_VAPID_SUBJECT` | 运维联系 `mailto:` 或有效 HTTPS URL。 |
| `PUSH_ALLOWED_HOSTS` | 精确 DNS 主机名逗号列表；默认 Google、Mozilla、Apple 三个标准主机。没有通配符。 |

使用锁文件中的 `web-push` 的 `generateVAPIDKeys()` 一次性生成 VAPID 密钥，直接写入受控密钥存储，不复制到 Git、日志、截图或终端共享记录。上述四个必需值只配置一部分会使进程启动失败。出站仅允许受信任主机的 HTTPS/443，要求能解析到公网 IPv4，固定解析结果建立 TLS 连接；不跟随重定向。当前不支持仅有 IPv6 的推送端点。

API 接口：`GET /v1/notification-push-key`；`PUT /v1/notification-subscription`。后者要求当前身份、CSRF、有效浏览器加密密钥及允许的服务端点，只返回设备 ID、版本、启用状态。端点、浏览器 auth 和 p256dh 被 AES-256-GCM 加密，AAD 绑定租户、主体、会话和设备；数据库只另存不可反解的 keyed fingerprint 用于同一端点换绑。

## 投递与故障语义

通知派发与系统投递分开循环；慢推送服务不占住通知事件派发循环，但仍共享有限数据库池。Worker 公平扫描有订阅的设备，每设备每轮最多领取一条。每条通知版本/设备最多尝试 5 次，数据库记录次数和 30 秒租约；可重试错误按 30/60/120/240 秒递增等待，进程重启不重置次数。

发送前检查当前会话、主体、来源 ACL、通知版本、已读、静音、DND 和订阅版本；DNS 解析与请求加密后再次执行检查。2xx 表示推送服务接受，不表示操作系统已显示；404/410 清除该版本订阅并停用设备；429/5xx/连接错误有限重试；其他 4xx、重定向、权限失效终结此提示。旧投递回执无法停用已轮换的新订阅。

传输超时或服务崩溃可能造成同一通用提示重复送达，不能宣称 exactly-once。浏览器使用同一通知定位 ID 作为展示 tag；系统通知没有业务正文、聊天名称、任务标题或 Agent 输出。点击固定打开同源通知收件箱，重新认证和读取当前权限下的条目。已进入推送服务或操作系统的提示不能远程保证撤回；因此即使源内容随后删除，系统提示也不含该内容。

退出、会话过期、当前主体不可用或手动停用阻断后续投递。设备列表可停用其他登录会话；订阅不等于任务接受、审批、已读或业务完成。系统通知不自动标记已读。

## 密钥轮换与恢复

当前密文没有多密钥 keyring。轮换加密密钥前停用并清除所有历史订阅密文和 fingerprint，再重启 API/Worker，要求用户重新订阅；不能直接换密钥后继续宣称旧订阅可用。VAPID 密钥轮换同样需要浏览器取消旧订阅并重新启用；可在浏览器站点设置中清除旧订阅。为兼容未来多密钥轮换，后续迁移须引入 key ID 和双读/单写窗口，不能从密文推断密钥。

数据库恢复必须先处于隔离状态；完成隐私账本重放及当前身份/权限核对之前，禁止启动推送 Worker。尤其不能让恢复出的旧登录会话或订阅直接连接厂商服务。恢复后建议先清空订阅，明确重新登记。密钥备份和访问审计由部署密钥管理系统承担。

## 实际设备验收清单

以下仍是待执行的生产/设备门槛；协议注入测试不能替代：

1. 在实际 Chrome/Firefox/Safari、目标 Android/iOS 设备上，完成 HTTPS/PWA 安装和用户主动授权，记录浏览器/OS 版本、权限状态与时间。
2. 从另一主体发送真实消息：前台、后台、浏览器关闭等受支持状态分别观察通用通知；点击仅打开当前可访问收件箱，无私密内容进入锁屏。
3. 拒绝权限、清除站点数据、撤销 OS 权限、会话过期、退出/切换账号、停用设备和订阅失效后，验证不继续发送敏感信息，不静默重开权限。
4. 实测 DND/静音、网络暂断、厂商 429/5xx、重复通知、多个会话和订阅轮换；记录服务接受与系统显示的区别。
5. 查看日志和数据库备份，确认无订阅 URL、浏览器密钥、私钥及业务正文泄漏。记录最终提交、密钥版本（不记录值）、迁移 029 和测试证据。

参考：[web-push 官方协议实现与配置](https://github.com/web-push-libs/web-push)、[MDN PushManager.subscribe](https://developer.mozilla.org/en-US/docs/Web/API/PushManager/subscribe)。本清单不保证所有浏览器在所有后台状态均会送达。
