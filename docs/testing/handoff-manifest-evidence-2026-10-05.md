# 交接行动清单实现与验证

日期：2026-10-05（Asia/Shanghai）。本轮补齐先前只允许空数组的交接协议字段，涵盖人类 UI、机器 API 和 Agent SDK。当前任务 owner 可读取待处理行动编号快照；任务参与者不因此获得 owner 专用端点，接收提案也不因此获得行动详情、参数或底层资源权限。

创建、修订和接受使用同一任务根锁检查同任务引用及当前待处理集合。拒绝未知/其他任务引用；遗漏返回 HANDOFF_ACTIONS_CHANGED。发送后新建行动与接受交接竞争时仅一方成功；已列行动正常完成后仍可接受，不因进展强迫无意义重签。100 项以上返回 HANDOFF_ACTIONS_LIMIT，不返回截断后可接受的清单。预览先检查当前 ACL，再读取当前 owner；预览不做任务生命周期判定，正式命令继续检查当前生命周期。

Web 对非空清单要求明确勾选编号披露，发送后详情显示固定编号；参数正文没有混入提案。首次 9 项浏览器批次 8 通过 / 1 超时，停在请求列表：默认筛选“收到的”，测试以发起人查找自己发送的请求。修正为显式切换“发出的”；新场景独立通过（7.0 秒，含环境启动批次 24.0 秒），没有增加超时或删去确认/隐私断言。

机器 SDK 新增 getTaskHandoffActions 与 createTaskRequest。实际 HTTP 的人→Agent→Agent 测试改用 SDK 发起二次交接；接单前读取被拒绝，接单后当前 owner 可读，缺少 tasks.read scope 被拒绝，ACK 与接受仍分离。机器补验批次 10 项通过（16.80 秒）。

初始完整 pnpm verify 通过工程、契约、类型、lint 和 181 单元；机器端增量后重新生成契约、构建受影响包/API、检查测试类型与相关 lint。最终增量批次结果附后。全量远程结果仅能用于其明确关联的提交，不以之前 10f5ba3 的 CI 证明新增业务源码。
