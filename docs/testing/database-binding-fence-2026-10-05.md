# 旧执行写入的数据库约束验证

日期：2026-10-05（Asia/Shanghai），父候选 9a23f2c。

连接绑定检查位于新服务代码时，仍运行的旧执行器可以尝试使用历史无摘要授权。迁移 036 在事务提交时约束新授权与 prepared/in_flight 尝试：必须存在格式正确的连接摘要，否则事务回滚；历史行不回填，终态处理保留。约束使用应用角色可见行，不提升权限。升级、回退和数据库恢复顺序见 [连接配置约定](../development/tool-configuration-binding.md)。

新增三个展开场景使用真实 PostgreSQL 与受限应用角色，刻意绕过新服务检查而执行旧 SQL 形态：无摘要授权插入提交失败；无摘要历史授权不能新建 prepared 尝试；已有 prepared 尝试不能提交 in_flight。验证 SQLSTATE/约束名称、事务回滚、零工具请求及零外部效果；最后一项继续通过新服务 abortPrepared 进入 failed，证明未执行清理没有被约束阻断。旧数据通过 owner 删除测试授权摘要构造，属于历史形态模拟，不冒充实际旧二进制执行。

安全边界：数据库只验证摘要存在与格式，当前配置相等性仍由新服务和签名恢复账本保证。已在网络上发出的副作用不能撤回；旧恢复程序必须停止并升级。保留数据库约束的消息 API 回退不等同于旧执行栈回退。此轮不能解除生产滚动升级、备份恢复或 AC-21 的剩余门槛。
