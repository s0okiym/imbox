# 账号与绑定邀请验证

日期：2026-10-05（Asia/Shanghai）。本轮补齐未入组账号自我识别/退出、管理员创建/撤销邀请、接收人预览并确认加入的完整流程。具体操作见 [邀请说明](../operations/member-invitations.md)，迁移 032 增加强制租户 RLS 的邀请表。

## 实际验证范围

真实数据库测试覆盖准确账号绑定、外租户工作区拒绝、已有成员不能借邀请恢复、一次消费与并发接受/撤销、原命令重试、过期/重新创建、邀请者权限改变后恢复仍失效、独立账本不可用，以及账本写入后数据库回滚的保守重放。慢账本写入跨过期限时，最后状态转换失败，成员与工作区授权全部回滚。

HTTP 回归使用真实 Cookie 会话，验证未入组账号可读自己的有限档案，而组织接口仍拒绝；预览和接受要求同源 Origin/CSRF，Bearer 不能冒充人类账号。OIDC 集成模拟提供方的真实回调也覆盖首次账号可见性；不代表生产 IdP 已验收。

Chromium 两个独立上下文验证管理员创建、接收人取得自己的 UUID、退出/重登、预览指定组织/工作区/角色、明确确认、加入后刷新保持访问，以及管理员撤销另一份未使用邀请。邀请码使用密码字段，仅暂存在内存，测试检查本机持久存储不含该码。

## 失败与修正

初始恢复夹具删除域事件时受到通知队列外键约束，改为在独立消费事实落盘后注入数据库事务失败，再执行实际账本重放；不把该案例描述为完整备份恢复演练。修正后原 24 项相关认证/邀请测试通过。

第一轮完整集成为 35 文件 / 275 项通过；当时完整浏览器为 30 通过、1 失败。失败是新增邀请码的只读 textarea 未被精确标签定位器识别；改为密码输入字段，既隐藏凭据，又提供稳定标签定位。后续加入邀请预览与慢写入过期验证，所以该早期全量结果不作为最终源码的完整通过证据。

最终相关认证/邀请批次为 26 项通过（8.98 秒）；邀请浏览器专项 1 项通过（26.4 秒），未增加重试或延长等待掩盖失败。最终全量、容器与源码身份另见 [结构化记录](member-invitations-local-2026-10-05.json)。CI 浏览器输出增加邀请码模式脱敏，并以合成样本验证规则；原始诊断与测试会话不作为公开证据提交。

## 保留边界

邀请码只由人自行通过可信渠道分发，系统不自动发邮件。组织自动发现/切换列表、开放自助组织开户、真实生产 IdP/公共证书和目标设备矩阵仍未完成；既有受控 CLI 首次开户继续有效。本轮不调整 AC/INV 的 27 verified / 13 partial / 1 pending，也不解除生产门禁。

最终全量结果：`pnpm verify`（181 单元）、277 集成（220.53 秒）、31 浏览器（5.9 分钟）、1 真实模型（10.71 秒）及 3 项容器验证（21.29 秒）全部通过。四种镜像均从本轮应用源码重建；之后仅补 CI 输出脱敏和文档，不改变镜像业务内容。容器使用本地 CA 与测试会话，验证生产依赖、非 root/只读文件系统、HTTPS/WSS、Cookie/CSRF、Worker 投影及 API 重启，不宣称公共部署已验收。
