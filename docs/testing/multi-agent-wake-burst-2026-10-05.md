# 多 Agent 有限唤醒突发验证

日期：2026-10-05（Asia/Shanghai）。父候选 `c988fa8`。本轮新增调度与 Runtime 的联合集成回归，使用真实 PostgreSQL 和 8 个独立 Agent principal/installation/Run，不调用模型或外部工具。

在同一任务树中创建 8 个已暂停 Run 与显式授权的有限计划，通过数据库时间夹具使计划到期，12 个并发扫描调用只产生 8 个 occurrence。派发前通过业务接口停用两个计划，12 个并发派发调用总计只唤醒 6 个 Run；停用 Run 保持 paused，其余 queued，各计划只有一条 occurrence。重复扫描与派发都返回零，每个 Agent 尝试创建递归计划均被拒绝。

六个 Run 同时领取租约，精确四个成功、两个 CAPACITY_EXCEEDED。四个有效租约各尝试预占 60，在共享任务预算 100 下精确一笔成功、其余 BUDGET_EXCEEDED，数据库 reserved=60。最终仍只有原来的 8 个计划和 9 个 Run（包括原始未参与突发的夹具 Run），恰好六条 run.schedule_wake 事件，不因重复唤醒增建 Run。

这证明有限计划、停用重验、根并发限制和共享预算在一次联合流程中成立，不代表模型驱动的 Agent 互相唤醒网络、任意事件触发、多租户长期压力或生产吞吐已验收。AC-15 / INV-11 仍 partial；当前事件调度扩展与跨租户混合压力继续保留。
