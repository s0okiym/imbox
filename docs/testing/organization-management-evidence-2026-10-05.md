## 实现范围

新增 human 组织 owner/admin 专用管理服务、六条 API、严格 DTO/OpenAPI、Web 管理页面。覆盖工作区创建、已有成员添加/角色/停用/恢复、最后管理员保护、幂等重试、版本竞争和独立撤权重放。Agent 行只读，资源 ACL 与组织管理权分开。

成员变更递增目标租户授权修订，防止旧运行在停用后再恢复。降权/停用写入独立签名账本 `revocation.workspace_member`；回退须有兼容读取器，无新增数据库迁移不代表旧二进制兼容。

## 实际断言

`tests/integration/organization.test.ts` 的 8 个用例覆盖：

- 组织管理员/普通成员边界、跨租户候选与成员拒绝、管理权不授予资源读取权。
- 创建命令去重、游标跨用途拒绝、成员变更后的旧游标拒绝。
- 停用与恢复分别使旧授权失效；重复的旧停用命令不能覆盖更新的明确恢复。
- 同一工作区版本的并发修改只有一个成功，领域事件只写入一次。
- 文件账本真实写入、模拟旧数据库状态后的撤权重放、更新的明确授权不被旧事实覆盖。
- 账本写入失败时成员和工作区版本都不变化。
- 真实 Cookie/CSRF/If-Match/Idempotency-Key API 操作与拒绝路径。
- 实际持久 Run 在创建者降权并恢复后仍拒绝领取和内容读取；创建者能显式取消旧 Run，并以新授权创建可领取的新 Run。

浏览器使用真实 API/数据库，覆盖管理员创建工作区、明确添加 Bob、停用、恢复为访客、最后管理员保护、刷新后读取，以及普通成员看见管理边界。测试创建的工作区在用例后单独清理，不改变种子工作区权限；正常撤权产生的授权修订不会被测试伪造回旧值。

## 发现与修复

1. 初次浏览器验证使用精确隐式 label 文本匹配下拉框，未计入选项文字。改用 combobox 可访问名称定位，没有增大等待时间。
2. 全量本地检查在浏览器失败后扫描到了 Playwright 报告中的生成脚本。ESLint/Prettier 忽略报告、测试产物目录；源码、测试和断言仍正常检查。
3. 实际 Run 的首次测试假定恢复后可读旧 Run；现有安全边界要求旧创建授权仍拒绝内容读取。改为验证读取拒绝、显式取消及新授权运行成功，不放宽旧内容权限。
4. 完整浏览器运行发现首次选择默认工作区时的二次加载窗口：界面短暂开放创建按钮，随后加载状态使 submit 返回，未发送请求。已修复为初始化选区完成后才开放操作；修复后的管理专项与全量浏览器批次均通过。
