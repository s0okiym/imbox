# 平台取消与执行器停止确认

日期：2026-10-05（Asia/Shanghai），父候选 1acc521。迁移 034 为 agent_runs 增加独立 cancellation_acknowledged_at；RuntimeRun 以可选字段兼容旧响应。历史记录默认未知，不反推远端停止事实。

只有当前有效租约提交 cancelled 回报才写入数据库确认时间。平台控制取消和租约失效不会填写该字段。幂等重放保持同一次确认时间。Web 分别显示状态与确认：外部 Agent 标注“远端自报，未独立验证”，缺失确认时不宣称远端进程已停止。

真实 PostgreSQL/HTTP 回归：新 SDK 实例重新交换同一 Agent 凭证，获知取消请求；此时 completed 回报与输出发布被拒绝。取消确认在 HTTP 服务已提交后主动丢弃响应，SDK 使用原键重试成功，只有一条 run_reports，重复读取的确认时间不变。第二个 Run 用数据库时钟构造过期租约后由平台取消，确认仍 NULL，旧 Worker 回报被拒绝。此用例模拟协议重连和回执丢失，不是独立机器/进程断电部署演练。

验证结果：

- `pnpm verify` 全部通过，34 文件、191 单元，9.74 秒。
- agents/runtime 两文件 34 集成通过，31.89 秒。
- 两个运行 UI 浏览器流程通过，47.3 秒：未领取执行租约的取消显示未确认；运行中请求取消后，执行器回报停止，再刷新显示确认时间。
- 回归目录 87 文件、501 条声明；此声明数不等于执行通过数量。

仍缺：过期租约后不恢复执行权的独立迟到确认通道，以及真实远端部署的失联/恢复/停止证明。AC-14 保持 partial，不能把平台取消、有效租约下的确认或本地 SDK 重连解释为完整生产远端停止保证。整体仍 27 verified / 13 partial / 1 pending。
