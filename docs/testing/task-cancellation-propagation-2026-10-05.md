# 任务终止与执行取消联动

日期：2026-10-05（Asia/Shanghai）。父候选 a06867e；不新增数据库迁移。

原先 Task 取消通过祖先状态与 execution_epoch 拒绝新执行，但相关 Run 可能继续显示 queued/running，也没有明确的 cancellation_requested。现在 cancel 和 failed 在原有任务根锁、幂等命令及数据库事务内调用执行联动：本任务及后代任务的活动 Run 收到取消请求，持有效运行租约的变为 cancelling，其余变为 cancelled；待执行 Action 和有效审批同步撤销。执行中/结果未知的 Action、执行回执、费用保留及最后领取代际保持不变。后代任务合同本身不自动取消。

运行停止确认仍由执行器回报提供，Task 终止不会填写 cancellation_acknowledged_at。执行器可通过心跳获取取消请求，完成输出被拒绝，cancelled 回报可以写入停止确认。过期外部执行器继续使用既有的受限迟到确认通道。完成验收继续使用既有执行闭合检查，不调用本次取消联动。

Task 服务未注入执行联动、但任务树仍存在活动 Run 或待执行 Action 时，命令返回 SERVICE_UNAVAILABLE，任务状态和版本一起回滚。没有执行对象的独立 Task 服务保持可用。API 入口显式连接 Runtime 与 Actions 两个事务内适配器。

真实数据库回归覆盖：取消/失败两条路径、后代活动 Run、本任务排队 Run、无关任务不受影响、幂等重放、缺少配置回滚、心跳取消信号、拒绝完成输出、停止确认以及五个微单位的费用保留。Action 回归使用真实 HTTP 产生一次外部效果并丢弃回执，验证取消仅撤销待审批/ready Action，unknown 不被伪装成取消成功。

测试夹具修正：原 runtime 快捷任务将 acceptance_criteria 写成对象，仅 Runtime 测试未暴露问题；本轮调用真实 Task DTO 后发现契约错误，改成合法验收条件数组。浏览器夹具显式接入和导出 Task 服务；初次类型检查发现重复属性，修正后重跑。

证据边界：本轮为本机 PostgreSQL/HTTP/Chromium 验证；不证明跨主机网络分区、TLS 部署和远端主机重启后的停止事实。AC-14 保持 partial。

浏览器首轮发现真实读取缺口：取消会改变 Task 输入版本，原 getRun 因旧上下文版本返回 409，界面无法显示停止状态。修复后仍先检查当前访问权限和双方执行身份；仅取消请求已存在且上下文版本冲突时，Run 单项和列表返回状态/费用元数据并清空 summary/output。上下文清单继续执行原校验，不返回旧内容；权限撤销和身份失效不被吞掉。集成回归使用预先存在的摘要/输出验证脱敏读取，浏览器覆盖包含真实 Task 输入的取消与停止确认。

状态读取修复的首轮浏览器复验还发现 HTTP 契约要求 summary 为字符串；脱敏使用空字符串、output 使用 null。集成服务调用本身不会代替 HTTP 响应契约检查，因此保留真实浏览器复验。

已执行集成批次：首次补齐联动后 tasks/runtime/actions 三文件 63 项通过（70.00 秒）；增加旧输入冲突下的状态读取后同三文件 63 项通过（58.61 秒）；摘要修正为契约允许的空字符串后 runtime 单文件 25 项通过（13.15 秒）。这些是分批验证，不能相加宣称独立用例总数。

最终验证：Runtime 包重建、测试类型与全仓 ESLint 通过；34 文件 191 单元通过（11.50 秒）；真实 Chromium 两个取消/确认流程通过（37.2 秒）。本轮较早的 verify 已通过环境、契约、完整构建、运行依赖与各包类型检查，后续测试类型夹具错误已修复并单独复验，不将该次退出非零的 verify 记作一次完整成功。回归目录为 87 文件、507 条具名声明，声明数不是执行数量。
