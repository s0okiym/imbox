# Artifact 冲突分支与显式合并

日期：2026-10-05（Asia/Shanghai）。基于 1330c43，新增数据库迁移 033、HTTP/契约和 Web 流程。

分支固定基础版本、草稿资源和作者，不移动主版本。保存分支不要求主版本仍停留在草稿基础上，因此主版本发生竞争变化时仍可保留用户修改；当前编辑权限及资源范围必须有效。合并要求用户上传已核对的完整内容和当前 Artifact 版本，服务端重新验权、串行校验主版本，记录基础版本、合并前主版本、生成版本及作者/合并者。原始草稿和历史版本保持不可变。

浏览器新增“保存为独立分支”、分支分页、基础/当前主版本查看、草稿下载与“上传整理后的合并内容”。合并确认说明主版本和具体文件，必须勾选已核对；版本改变时拒绝，用户重新核对后才能重试。分支对当前产物范围内的可读成员可见，不是个人私密草稿。

新增真实 PostgreSQL/S3 回归覆盖：分支创建幂等且不移动 head；Bob 草稿与 Alice 后续修改独立；旧主版本合并拒绝；整理后内容成为新版本；原稿、base/merge-against/merged 标识保持；同键重放不重复合并；同一主版本竞争合并只成功一个；外来基础版本拒绝；分页；删除草稿内容后不能合并；数据库不可变和跨租户 RLS；200 个活动草稿上限及删除内容后释放名额。

首次浏览器扩展暴露了连续追加时的旧命令基准：第一次成功后新编辑仍沿用上次基准，按钮被错误禁用。修正为开始新的上传/整理操作时采用当前显示版本，仍保留提交时 If-Match 检查。没有增加超时来掩盖该问题。

外部发布 Action 的旧批准/新产物联合矩阵尚待完成，AC-18 仍 partial。此功能提供人工明确整理后的合并，不实现自动三方文本拼接或实时 CRDT；也不把合并当作任务验收或外部发布。
