# 委派拒绝后的重新安排

日期：2026-10-05（Asia/Shanghai）。浏览器场景使用三个独立 Chromium 会话和真实 API/数据库：Alice 创建并启动父任务，向 Bob 委派；Bob 阅读后明确拒绝。拒绝状态可见，Bob 的任务列表不出现相应子任务，Alice 仍为父任务负责人并可继续提交结果。Alice 随后调整提案标题并委派给 Charlie；Charlie 明确接受后打开唯一子任务，确认自己为负责人，同时没有父任务的访问入口；Alice 仍负责父任务。

该场景与现有 Task 集成测试的“拒绝/过期不创建 child、接受只创建一个 child、父 owner 不变”共同覆盖 AC-05。浏览器不通过直接 SQL 修改状态，也不把阅读或点击发送当作接受。
