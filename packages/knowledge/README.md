# Explicit memory and permission-aware search

`createKnowledgeService({db,cursorSecret})` provides explicit Memory creation, revisions, reads, disabling, confirmation, expiry and deletion, plus bounded search. `registerKnowledgeRoutes(app,{identity,knowledge})` mounts `/v1/memories` and `/v1/search`. Memory creation, modification and deletion require a human identity at the service boundary. Agents may read permitted content; an Agent cannot label its own new assertion as human-confirmed.

Each Memory has exactly one personal, conversation or Task scope. Sources pin a message, Task or immutable Artifact version by ID, version and SHA-256. Personal derived memory still requires all source permissions on every read. Shared memory accepts sources only from the same scope. Source edits, deletion, visibility generation changes, original-author membership changes and identity disable/re-enable cannot revive an old derived assertion. Modification explicitly supplies new source references and uses If-Match. Confidence and confirmation are human-supplied metadata, not model confidence estimates. Conflicted or unconfirmed records can be reviewed but are excluded from search and context reads.

Stored content is always `user_content` with `instruction_authority: none`. Natural-language text, even text requesting approval or claiming to be a system prompt, never changes authorization. `readMemoryTx(tx,auth,id)` requires an active, confirmed, unexpired Memory and fresh source checks. `readSourceTx(tx,auth,ref)` performs source and scope checks inside the caller's transaction; it does not grant Run execution or disclosure rights on its own.

Search covers visible message bodies, Task title/goal/acceptance criteria, Artifact version text/title/filename and active confirmed Memory text. It applies PostgreSQL tenant RLS and current scope predicates before matching or pagination, then locks and checks returned sources again before producing snippets. Since-join history, Task participants and workspace membership apply. Results include fixed references, no private counts, and no snippets from inaccessible candidates. Opaque cursors bind the caller, normalized query, filters and current membership generations. Pages are live ordered views, not a snapshot of earlier search results.

Queries normalize Unicode NFKC, case and whitespace. Literal character matching handles Chinese and mixed text; PostgreSQL simple-dictionary full-text matching also accepts English terms in different orders. Queries require 2–200 normalized characters, return at most 50 results and have a five-second database deadline. PostgreSQL expression/trigram indexes are provided; realistic tenant-scale latency and relevance benchmarks remain a release validation task. This is not Chinese word segmentation, semantic/vector search or relevance ranking.

`knowledgeResourceIndex()` is injected as `createResourceService({textIndex: knowledgeResourceIndex(), ...})`. It indexes only bytes already checked for size, hash and text policy, within the final metadata transaction. Artifact queries join current approved resource metadata/version/hash and tombstones, so a stale document cannot expose withdrawn text. Existing resources created before this hook was installed have metadata search only until an authorized, hash-verified backfill runs. No source objects are downloaded during a search transaction.

`createKnowledgeReconciler(db)(tenantId,limit)` is a bounded internal maintenance job. Reads reject invalid provenance immediately. The job then marks invalid/expired Memories restricted, clears retained revision bodies and records durable deletion receipts; it also removes stale resource text documents. Explicit Memory deletion clears all revision bodies in its transaction. These database receipts alone are not an independent backup-restoration ledger; the platform governance/recovery layer must replay tombstones before reopening a restored database.

Memory revision bodies are retained for auditing until explicit deletion or provenance cleanup. Vector embeddings, automatic candidate generation, model-driven confirmation, automatic cross-scope sharing, public Run summaries and third-party deletion acknowledgements are not implemented here. Runtime and scheduling must use the injected source port and revalidate at their own execution boundary before claiming these content types are connected to model execution.

Real PostgreSQL, S3 and HTTP validation: `pnpm exec vitest run tests/integration/knowledge.test.ts --config vitest.integration.config.ts`. Missing configured databases/storage fail rather than silently skipping.
