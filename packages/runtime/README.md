# Durable agent runtime

`createRuntimeService({ db })` provides installation of immutable agent revisions, Run creation, creator-scoped reads of Runs/manifests and versioned pause/resume/cancel commands. `registerRuntimeRoutes` exposes these human-authorized commands. An agent Principal must already exist and be an active tenant/workspace/task or conversation member. Provisioning machine credentials is a separate capability.

`createRuntimeWorker({ db, workerId, leaseSeconds })` is an internal capability. Its claim, heartbeat, report and accounting methods have no public HTTP routes. A hosted driver uses:

1. `listRunnable(tenantId)` to discover durable candidates, then `claim(tenantId, runId)` to acquire an expiring PostgreSQL-clock lease. Candidate discovery does not authorize execution.
2. `getExecution(claim)` to read the immutable revision, manifest destination/purpose and explicitly selected context items. A driver must constrain supported providers/destinations itself; configuration is not authorization to contact arbitrary URLs.
3. `reserve(claim, { reservation_key, amount_microunits, currency })` before a model call. Dispatch only when `newly_reserved` is true. Reusing a reservation is not permission to dispatch again. Revalidate execution immediately before dispatch and renew the lease during long work.
4. `completeStep(claim, reservationId, { usage_key, actual_microunits, evidence }, checkpoint)` atomically records actual billing and a running result checkpoint. `getExecution().latest_checkpoint` lets a new lease recover that result without repeating the model call. When a revoked/expired lease cannot save content, use accounting-only `settle(tenantId, reservationId, usage)` for the late billing fact. A timeout becomes `markUnknown`; only positive no-charge evidence permits `release`. Unknown cost remains reserved. Local zero-cost execution must explicitly record its pricing policy rather than invent a provider receipt.
5. `report(claim, { status, checkpoint, summary?, output? }, reportKey)` to commit an authorized checkpoint/result. Completing a Run requires every reservation to be settled/released. The caller must use a stable report key on retries.

All writes use tenant RLS and database transactions. Lease holder, generation and expiry are checked even without a takeover. Task ancestors are locked root first and every captured execution epoch must remain current. Global principal versions, tenant authorization revisions, installation revision and scope membership generations are frozen: disabling then re-enabling a principal or removing then re-adding a participant does not revive a Run. PostgreSQL serialization/deadlock failures retry the entire database-only transaction up to three attempts; external work never runs inside this callback.

Each reservation produces one usage fact. Root and descendant budget counters are admission constraints over that same fact, not independent charges to sum together. Concurrent children share their root limit. Late accounting is accepted after cancellation, and actual overspend is persisted with a blocked account rather than rolled back. Unresolved reservations after lease loss move the Run to `waiting_dependency`; a new worker does not repeat an uncertain model call.

Context consists only of explicit message/task references with versions, hashes, source trust and authorization evidence. Conversation Runs cannot ingest task content. Optional inaccessible references may be omitted at creation; included sources are rechecked before execution and result submission. Context-derived output is creator-only and cannot be read after a source is revoked or changes. Existing 006-era Runs receive invalid fences in migration 007 and must be recreated. Global principal changes occur in the identity database pool: there remains an ordinary in-flight transaction boundary between the last global read and commit; subsequent commands reject stale principal versions.

Cancellation heartbeat returns the stop signal without renewing authority. A worker acknowledges a safe pause/cancel checkpoint. This package does not forcibly terminate an OS process. `runtimeCompletionGate(tx, taskId)` composes with the Action gate inside the Task command's root-locked transaction and checks all descendant Runs and unresolved usage.

Current boundaries: model adapters and dispatch loops live outside this package; external tool execution, Action reconciliation and machine credentials are separate modules. No model output is fabricated here. Runs and their contexts currently have direct creator-scoped read endpoints, not a general paginated Run browser or realtime Run projection. Worker identity comes from trusted in-process composition, not a caller-supplied web identity. Model/tool operations cannot be made atomic with a PostgreSQL commit; drivers must preserve uncertainty and reconcile before retrying external work.
